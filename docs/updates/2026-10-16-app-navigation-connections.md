# 长者 App 顶部导航与亲友连接方案

## 1. 本轮产品结构

App 顶部固定：侧边菜单、小叙、消息、大圆相机。取消底部三个入口和大加号。聊天输入条上的附件加号继续保留，用于添加照片、声音、视频、文章，不承担全局导航。

侧边菜单从左侧滑出，背景不虚化：新对话、小叙头像及最近对话入口、发祝福／发日常／我的拾光／添加亲友、最近聊过、对话案例、底部我的。

新对话创建独立会话，不清空之前的会话。菜单能恢复此前对话，顶部显示对应主题。首页三条可轮换提示语表达用户意图，不是固定功能九宫格。新会话更换提示组，也可手动换话题。提问示例只覆盖现阶段可触达功能，不以未接通的服务作为已实现能力。当前提示语为本地模板轮换，不是真实个性化推荐。

我的：个人资料、我的拾光、我的相框、微信账号、我的亲友。移除发过的日常入口；消息继续承担按人查看及续聊。

## 2. 长者与亲友连接

没有参与荣休礼的人也应可以添加长者。共创关系和通信关系分开：参与过礼物，不等于可以未经同意持续发消息；获准连接，也不要求参与过礼物。

主流程：
1. 长者在 App 的菜单或我的亲友里选择添加亲友。
2. 生成邀请链接和邀请码，发送给认识的人。亲友可从邀请链接进入小程序，也可以在小程序“我的／我参与的人”进入添加亲友，输入邀请码。
3. 展示长者姓名供核对；亲友填写本人姓名、自己是长者的什么人、可选留言。
4. 提交后进入待确认状态，不提前给亲友发送权限。
5. 长者看到姓名、关系、留言，选择同意或婉拒。
6. 同意后建立双向连接，亲友进入消息／收件人选择；关系支持解除。解除后不允许继续使用过期收件人选择发送。

角色方向始终是“申请者是长者的什么人”。不因姓名相似自动合并账号，不把通讯录同名视为同一人。邀请链接不能直接登录长者账号，也不能直接绑定或管理相框。

状态：未申请 → 待确认 → 已添加；待确认可婉拒，已添加可解除。被婉拒后允许重新申请，但正式产品应限频。解除时二次确认，历史内容不因关系解除而自动删除。

边缘处理：无效／过期邀请不提交；重复待确认或已添加申请不重复创建；刷新保留申请状态；更新邀请码使旧码失效；本轮演示邀请有效期7天。正式端应补充撤回申请、拉黑、防骚扰限频、系统通知、对方账号注销等分支。

## 3. 正式账号与邀请服务规则

邀请简介可匿名查看。提交申请、查看申请列表、批准、解除、发送内容必须登录。生产环境使用稳定账号 ID 去重，不能依赖姓名。邀请由服务端生成不可枚举 token，并校验收件主体、有效期及撤销状态。

建议接口：
- POST /elder-invitations：登录长者创建或更新邀请；返回脱敏介绍、token、到期时间。
- GET /elder-invitations/:token：公开的最低限度邀请简介，不暴露历史内容、手机号和设备信息。
- POST /connection-requests：申请者登录，提交邀请 token、自述关系、留言；幂等防重复。
- GET /connection-requests：仅本人可见的申请列表。
- POST /connection-requests/:id/accept 或 /decline：仅邀请所属长者可处理；原子化校验状态。
- DELETE /connections/:id：本人解除关系；同时撤销后续发送资格。
- GET /connections：当前获准收件人，发送时服务端再次校验。

小程序与 App 应归一到同一个账号身份体系，微信登录需由后端关联 UnionID／OpenID；不能靠手机号文本或昵称自动绑定。实名关系称呼只用于显示，不赋予设备管理权限。亲友帮长者操作设备，应另做明确的管理授权。

## 4. 相框与微信账号

我的相框展示绑定设备、设备名称、连接状态、最近同步时间、接收设置及管理入口。没有真实状态数据时不写“在线”。绑定流程应为 App 输入／扫描相框绑定码 → 服务端校验 → 相框侧确认 → 建立账户与设备关系。更换管理员、解绑和重置需分别确认，不能把清除设备等同于删除账户资产。

微信账号展示已绑定账号的头像和脱敏昵称，提供授权绑定、换绑／解绑；与某个亲友建立关系不等于绑定了对方微信。真实授权失败、取消、微信已绑定其他账号等情况不能显示成功。

本轮界面提供相框入口、绑定码输入和微信授权入口。服务尚未接通时明确反馈，既不伪造在线，也不伪造绑定成功。

## 5. 实现范围与验证

- /app/、/app-plus/ 均使用顶部导航，案例页嵌入同一新版本；原三按钮版本可从 Git 历史与旧部署版本恢复。
- 当前演示使用同源本地存储模拟申请状态。同一浏览器的 App／小程序标签页可同步；不同手机／不同浏览器不会真实同步。相框绑定、微信授权、真实消息发送仍需接入后端。
- 共享邀请组件位于 shared/，运行 node scripts/sync-connections.mjs 同步到 elder-app、miniapp、web 的 src/shared，避免三个项目分叉。
- 当前演示人物为陈明远／陈老师，正式产品须从邀请所属用户获取信息。当前本地演示姓名防重不能替代生产账号鉴权。
- 新会话和历史续聊为当前页面会话内保留，尚未新增云端对话历史服务。
- 验证包含新对话隔离、提示轮换、历史恢复、顶部导航、照片发送、拾光分类、账号页面；并在同源双标签页实测小程序申请 → 长者同意 → 申请者状态更新 → 新亲友消息入口。

## 6. 个人名片与布局统一

- 添加亲友首页改为列表：个人头像与「我的二维码」、邀请亲友、新的朋友、已添加的亲友。申请与关系列表各自进入二级页，使用顶部返回。
- 个人二维码为实际编码的邀请 URL，可保存 PNG 或通过系统分享；不支持系统分享时复制链接。邀请码与更新操作收起在次级入口。更新后旧邀请失效。
- 二维码只是邀请入口，不表示关系已经建立。仍需申请与长者确认；跨设备同步仍受第 5 节演示范围限制。
- 侧栏入口统一为「新话题」，下面列出具体历史标题，移除「我的聊天」「聊聊这些」重复层级。
- App 与案例内嵌 App 使用同一单行输入栏：键盘、按住说话、加号；移除独占一排的上传与朗读工具栏。消息自身的朗读功能保留。

### 侧栏常用入口精简

常用入口改为轻量图标列表「留一段回忆」「家谱树」。前者开启独立回忆对话，由小叙引导；后者直达家人关系树。发日常继续使用顶部相机，不在侧栏重复。我的拾光、添加亲友仍从「我的」进入。历史对话与新话题入口不变。

### 四个固定入口

侧栏最终显示「我的提醒、我的拾光、我的亲友、帮我看看」，统一暖米棕底、深棕文字与图标，保持与浅色页面协调。家谱树在我的亲友的家人标签中；发日常使用顶部相机。

我的提醒可新增、修改、暂停、恢复、完成及二次确认删除；按待提醒／已完成／已暂停查看。一次性提醒必须填写未来日期时间，每天提醒填写时间。语音转写可预填事项与数字时间，保存前必须确认。当前数据本地保存，不执行后台通知，不联动相框，也不表示已经设置系统闹钟。

帮我看看支持相册与拍摄入口、图片预览、语音或文字输入；提供标注为示例的社区通知及朗读。当前没有图片识别服务，不针对用户上传的照片编造识别结果。正式版应接入视觉理解服务后再实现读图问答。

提醒新增使用底部按住说话（键盘备用），移除「添加提醒」按钮。转写后预填事项及可识别的时间，支持数字／中文小时、半点、今天／明天及每天；缺少或无法识别的信息留空，由用户确认补充后保存，不默认猜测时间。
