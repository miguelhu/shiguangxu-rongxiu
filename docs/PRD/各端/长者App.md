# 长者 App PRD

更新：2026-10-14。当前唯一App规格，统一连续会话与全页面语音交互、账号、家谱、消息及数据规则；无需同时阅读旧V1／V2／V3。

快速定位：[导航](#app导航) · [语音](#app语音) · [记忆](#app记忆) · [发送](#app发送) · [家谱](#app家谱) · [验收](#app验收)。公共规则见[总览](../总览与公共规则.md)，能力编号与四文风见[AI能力](../公共能力/AI能力.md)。

## 1. 产品目标

长者通过说话、拍照或选照片，记录自己的拾光碎片、给亲友发送日常，并在需要时得到小叙帮助。小叙是持续理解上下文的助手，不是每完成一项任务就重新开始的问卷。

**所有 App 自有页面的可执行操作必须同时提供语音路径与可点击路径。** 包括导航、打开相机、切换镜头、拍照、重拍、选照片、勾选／取消选项、修改文字、挑选亲友、保存、确认发送、取消、返回、查看记录、调整设置和维护家谱。不得把“能语音输入正文”当成全语音操作完成。

语音不绕过系统相机／麦克风／相册授权、系统登录验证、设备解锁或付款等系统安全界面。首次授权仍由系统要求用户确认；授权完成后回到原任务继续。对此应明确提示一次，不承诺零触屏首次使用。

“我的”承接资料、本人记录、发过的日常、亲友和设置。首版不增加朋友圈、排行榜、群聊或共创者评论流；荣休仪式仍由相框承接。

## 2. 身份、账号与首次使用

| 系统 | 职责 | 与本 App 的关系 |
| --- | --- | --- |
| 长者 App | 长者自己的碎片、日常、亲友、操作帮助 | 本文范围 |
| 小程序 | 共创者／统筹者共创、赠礼、持续联系 | 同一个人的账号身份跨端一致，角色按上下文判定 |
| 相框 | 仪式播放、日常收礼、记忆浏览、长者回应 | 获授权同步内容；共用家谱和人物标识 |
| 展示网站 | 场景演示和工程沟通 | 不承担正式身份、送达或云端存储承诺 |

- 同一自然人以稳定 userId 表示；小程序授权身份与 App 登录方式映射同一账号，不按昵称自动合并。
- 家谱中的 personId 表示被记载的人，可没有账号；accountId 是可选关联。亲属关系不等于账号绑定、通讯录授权或消息接收许可。
- 联系人姓名取账号资料；长者设置的备注只对本人展示，不能改对方账号姓名。
- 正式内容从登录资料读取，不预置案例姓名、亲属或家谱。

### 2.1 登录与恢复

1. 展示产品名称与“登录”，不先要求完整个人档案。
2. 支持与既有账号体系一致的手机号验证／微信身份绑定方式；具体SDK由客户端方案确定。
3. 同一手机号遇到已有小程序账号，验证后进入同一 userId；不能仅根据同名联系人合并。
4. 首次进入只请求登录所需授权。照片、相机、麦克风、通知权限均在使用对应功能时请求。
5. 登录失效时保留加密草稿，重新登录后仅恢复相同账号的数据；退出登录清除可读会话与当前账号缓存索引。
6. 登录取消可返回登录页；不会静默切换到另一个人的陈老师案例或显示其他人的家谱。

## 3. 导航与双入口

顶部稳定保留“拾光”“我的”及圆形相机按钮，分别提供文字可读标签或无障碍名称。相机不是新的聊天助手，也不重复增加底栏。

- 拾光：欢迎语、连续聊天、按住说话、文字输入和媒体入口。
- 圆形相机：直接取景→拍摄／选图→补充一句话或声音→选亲友→确认发送。不必先与小叙聊天；但每个步骤都能用语音执行。
- 我的：个人资料、我的拾光、发过的日常、我的亲友（家谱／亲友）、设置。

“打开相机”“给女儿拍张照”与点击相机进入同一相机状态。“回到聊天”恢复原对话及未完成草稿，不清空。不同草稿通过 taskId 分开，不能把新拍的日常自动混进之前的回忆。用户明确说“把这张也添进去”时才关联指定回忆。

### 3.1 页面逻辑键

APP前缀表示长者App，逻辑键不要求独立URL；对话、相机与确认卡可共享页面状态。页面键供研发和AI调用定位，不显示给用户。

| 页面键 | 内容／入口 |
| --- | --- |
| APP.登录 | 首次登录、身份确认、登录恢复 |
| APP.拾光持续对话 | 拾光首页、连续记录与当前任务 |
| APP.快捷选项 | 当前消息的可点击／可说出的选择 |
| APP.圆形相机／APP.相册选择 | 真取景、拍摄确认、自有相册选择 |
| APP.记忆编辑／APP.查找记忆／APP.记忆详情 | 本人记录、查找和阅读修改 |
| APP.日常编辑／APP.联系人／APP.发送预览／APP.发送结果 | 独立日常草稿、选人、确认、逐人回执 |
| APP.我的／APP.个人档案／APP.发过的日常 | 本人资料、记录和发送历史 |
| APP.家谱／APP.成员详情／APP.家谱确认 | 亲友查看、提取候选与确认关系 |
| APP.来信／APP.设置 | 主动查看、回应、字号、通知、权限与退出 |

返回保留草稿、列表位置和家谱视角；详情回来源页，不一律回首页。确认卡关闭回原任务，录音切页先停止，不后台续录。旧E00—E17只是历史页面编号，不再代表四底栏入口。

## 4. 页面级语音契约

> AI对接：统一AI-11命令转写＋AI-19动作提案；由真实执行器实施。每页按钮与语音共用权限、状态和确认契约，逐页能力登记见[AI能力的App映射](../公共能力/AI能力.md#页面映射)。

| 页面／状态 | 语音示例 | 结果与确认 |
| --- | --- | --- |
| 所有自有页面 | 回去／取消／打开我的／回到拾光／你能帮我做什么 | 执行当前可用动作；有未保存修改时先询问保留还是舍弃 |
| 欢迎／聊天 | 记个回忆／给晓禾发日常／打开相机 | 切换任务意图，保留前序聊天 |
| 回复后的选项 | 第一个／选存起来／不是这个／换一种说法 | 按当前可见选项的稳定ID执行，与点击同一路径 |
| 相机 | 拍一张／三秒后拍／换前置／换后置／重拍／用这张 | 取景、可取消倒计时、拍照或确认使用；打开相机不等于拍照 |
| 相册 | 看下一页／选第二张和第四张／取消第二张／选好了 | 对 App 内可访问缩略图执行选择，显示勾选和总数 |
| 日常编辑 | 加一句“今天很开心”／删掉最后一句／听一下录音 | 定位对应内容并预览修改；指代不明先问 |
| 亲友选择 | 发给女儿／再加上周宁／不要周宁／选好了 | 匹配稳定accountId；重名给候选，不按猜测发送 |
| 发送确认 | 读给我听／确认发送／改一下／先不发 | 朗读、提交或返回；明确确认才执行发送 |
| 保存回忆 | 先存下／把刚才那句也补进去／换个话题 | 保存事务成功后反馈；同记录追加或新建任务 |
| 我的拾光 | 找和学生的合影／打开第二条／读这段／改标题 | 仅搜索有权访问内容；结果必须可追溯到实际记录 |
| 发过的日常 | 看发给晓禾的／重试刚才失败的 | 显示真实状态；只重试失败对象，不向已成功对象重发 |
| 亲友／家谱 | 打开家谱／这是我女儿／加一位家人 | 收集关系、身份后显示确认卡；不自动绑定账号 |
| 个人资料／设置 | 把字号调大／关闭自动朗读／改我的称呼 | 可逆设置立即反馈；账号删除等敏感操作单独核验 |

系统相册选择器不能被 App 的 Agent 控制。要满足“选第二张”的语音体验，正式客户端需在获得系统许可后使用 App 自有相册选择页，或将系统选择结果返回 App 后再语音调整。有限相册授权只展示获准素材，扩大范围要再次走系统授权。

### 4.1 收听状态与权限

各页面保留可触达的语音控制。默认支持按住说话；另提供“一次点击开始，再点结束”的免长按模式。相机取景中以小型麦克风状态条显示，不遮挡被拍人物和快门。

状态：未收听→请求权限→正在听→正在识别→理解／执行→回复。拒绝、超时、不可用分别呈现真实状态，保留文字和按钮替代。不能未获授权就持续录音。

用户主动开启“连续语音”后，可以在前台当前任务中连续发指令；清楚显示正在收听和停止入口。进入后台、锁屏、退出账号、切到系统权限界面时停止收听；回来不偷偷恢复。静默时限由配置确定并真机验证，超时提示后暂停，不丢任务。

用户说话时停止小叙朗读，避免回声被当作指令。TTS文字、播放状态和音量可控；不自动朗读别人来信正文。录音权限与相机权限独立，拒绝其中一个不阻止另一个。

### 4.2 录音细节

按住时权限弹窗返回前已经松手则不开始录音；上滑取消、触摸中断、来电等均停止采集，不静默发送。单段语音建议最长60秒，太短或静音提示重说；持续会话不以单段时长为结束条件，限值须按真机测试配置。原声、转写和整理稿独立，识别失败可保存真实音频或改打字，不伪造识别。操作语音不自动作为作品原声长期保存。

## 5. AI 回复与快捷选项

回复先回应用户刚说的具体内容，再在必要时问一个问题。语气亲切、平等，不哄小孩，不无根据推断开心、孤独或家人意图。不因信息缺项反复追问。

只在有决策需要时提供选项，通常2—3个；没有选项时也能继续自由说话。选项是建议，不是强制问答。

| 场景 | 回复示例 | 可点击／可说出的选项 |
| --- | --- | --- |
| 收到照片 | 照片放好了，想聊聊它，还是发给亲友看看？ | 存起来／发给亲友 |
| 一段讲述 | 想接着说，还是先看看我帮您整理的一小段？ | 继续讲／帮我整理／保留原话 |
| 改写预览 | 这样写像您想说的吗？ | 就用这段／再口语一点／用原话 |
| 找照片 | 是这张吗？ | 就是这张／不是这张 |
| 姓名不确定 | 您说的是女儿陈晓禾吗？ | 是她／换一位 |
| 发送前 | 这张照片和这句话，发给陈晓禾，对吗？ | 确认发送／改一下／先不发 |

每组选项携带 suggestionSetId、optionId、label、actionType、targetId、有效taskId和stateVersion。“第一个”只对应当前有效的一组选项；多组选项同时可见或刚切页时必须澄清。“好的”仅在唯一、无风险的明确提问中可作为选择；不能把模糊应答视为发送／删除授权。

用户说同义表达走同一动作，如“给她看看”映射分享意图，但对象未定时不能执行。旧选项失效后不执行过时动作，应解释并展示当前选项。点击和语音竞态使用同一幂等键，不能重复保存或发送。

## 6. 相机全语音流程

1. “打开相机”→展示取景；无权限请求系统授权，授权后继续。
2. “换前置”→切镜头成功反馈。设备无该镜头时说明，保留现有取景。
3. “拍一张”→拍照；“三秒后拍”→可见且可听的倒计时，任何时刻“取消”终止。
4. 拍摄成功→展示照片和“用这张／重拍／取消”。拍摄失败不跳转，也不生成空图。
5. “用这张，发给女儿”→照片加入日常草稿，解析对象，显示编辑／确认状态。
6. “加一句今天出去走了走”→文字可见；“读一遍”只朗读即将发送内容。
7. “确认发送”→服务端接受后显示发送中，按真实回执更新。

相机开启时语音监听不能要求退出取景；客户端需验证摄像头与麦克风并行占用。调用系统相机时若无法并行监听，返回 App 后恢复确认；正式版本必须提供 App 内拍摄以满足完整语音路径。退出取景立即释放摄像头。不得在后台拍摄。

## 7. 持续会话、任务与保存

一段会话可以有多项任务，但当前只设一个明确的执行焦点。保存结束的是当前写入操作，不是聊天。没有“再记一段才能继续”的页面。

用户补充原故事→更新原memoryId；明确换话题→新taskId与memoryId。无法判断“那次”“这个”指向时给候选，不擅自合并。分享记录使用独立ID，不能覆盖回忆。离开页面保留草稿，重新进入可恢复；正式产品本地加密草稿与云端同步策略需配合账号权限。

保存前无最低字数、必填年份或完成度门槛。有实际照片、录音或叙述之一即可保存；仅说“帮我保存”不构成回忆正文。保存失败保留原稿，不报告成功。用户舍弃只清除本次未保存修改，已保存记录保留；舍弃也可语音确认。

### 7.1 整理与检索

> AI对接：单人整理AI-03，事实提取AI-13，标题摘要AI-16，授权检索AI-17；日常表达AI-10，家谱AI-20，朗读AI-18。相同能力跨端共用编号，不共用用户上下文。

整理保留原始语音、转写和整理稿的关联，不改人名、年份、关系或关键事实。用户可语音逐句纠正，“不是老张，是老周”修改明确对象并展示结果。不得将操作指令混入故事。

段落→章节→小文表示内容逐渐丰富，不是进度任务，不是固定字数／百分比。时间不确定保留原话或未知，不推算为确定年份。

搜索仅在当前账号可访问的记忆范围执行，可结合人物、时间、地点、主题。没有结果就说明并给调整条件；候选不足时不拿固定图片假充命中。找到照片后可查看、讲故事、添加描述或分享，后续权限继续校验。

### 7.2 照片与媒体


媒体数量和大小按第14节建议值与最终配置校验。客户端支持常见相册格式，HEIC由系统或服务端转兼容预览；不支持的类型明确告知，不能生成坏缩略图。超限选择保留先前照片，不静默丢失。

逐张展示缩略图、删除按钮；点图放大返回原编辑页。裁剪和美化非首发必选。保留原始资产及方向信息，上传预览压缩不覆盖原图。默认不公开精确定位等EXIF信息。


### 7.3 原始记录与转写

有照片、有效录音或非空白文字任一项即可保存；仅标签或命令不算记录。语音转写异步进行，不阻塞原录音保存。原声、转写与编辑稿关联存储，迟到识别不覆盖人工修改。单条文字上限按第14节参数表冻结；无最低字数、不显示丰富度百分比，不以信息不齐强制追问。超限必须保留原稿并提供精简或拆分，不静默截断。

### 7.4 时间与标签


说“这是和女儿去杭州旅行时拍的”可生成“女儿／杭州／旅行”候选。人物、地点、话题分别存储，家人同名时不自动绑定 personId。标签可删除或修改；首次提取后显示简短确认，不在空白页要求填一堆标签。

日期使用 takenAt、precision（day/month/year/unknown）、source（EXIF/user/speech）、confidence。用户确认优先；识别出的含糊日期不补成确定年月日。“那年夏天”不能编造年份；“大概2010年”记录年份及不确定性。

单条多照片分别存拍摄时间。保存列表默认按创建时间倒序以便找回；“按回忆时间”浏览按拍摄时间升序，不确定日期置后、同时间稳定排序。不得把上传日期冒充拍摄日期。

同步到相框后使用相框既有排序／拼图规则；图中出现4个人不是合并4张照片的条件。App自身上传碎片不改写已经锁定的荣休仪式版本。


### 7.5 保存与同步

明确说“存下”或点击保存后直接执行，不新增强制预览步骤。保存操作不结束会话；可继续补充同一记录。云端确认才显示“已保存”；离线显示“已保存在本机，待同步”，失败保留内容。同幂等键不重复创建；修改产生revision。本人保存默认私人，相框同步须本人绑定与同步授权，加入家谱不使记录自动对全家公开。删除先说明源与同步影响，恢复期建议30天，最终按总览D-10冻结。

## 8. 收件人、发送与外部动作

> AI对接：AI-19不能用生成话术替代发送；确认令牌绑定收件人、内容版本、渠道，变化即失效。

亲属称呼与收件账号分开：personId不保证accountId存在。未绑定的家谱成员不能成为可达收件人；不把孙女误替换成女儿。重名显示关系、备注与可区分资料，支持“选第二位”。多人选择后必须读出／展示全部对象，允许语音逐一移除。

发送前展示当前内容版本和收件人集合；确认后如果任一项改变，旧确认失效，需重新确认。成功指服务端实际状态，不指点了按钮。排队、发送中、部分失败、全部失败、已送达分开；未读不能说已读。

删除记录、解绑亲友／相框、家谱关系变更等动作先明确对象、影响范围，再确认。用户话语中引用“删除”或回忆某人说“发出去”不应触发命令。登录验证码、系统权限不能由模型猜测或代填。

### 8.1 日常草稿与联系人

照片、原音或文字可独立发送，日常与记忆草稿独立。相机／选图取消保留已有内容，媒体上限参见第14节，不能用小程序限值默默覆盖App配置。联系人显示头像、姓名或本人备注、关系和选中状态；建议单次最多20人，生产值待冻结，超限不清空已选。无accountId的家谱成员不能发送。

### 8.2 逐人送达与恢复


每位收件人独立拥有：排队中→发送中→服务端已接收→已送达；读取／回应另存，可未知。HTTP请求成功仅代表服务端接收，不意味着对方已看。App被杀进程后任务由可恢复队列继续，使用同一幂等键。

全部成功、部分成功、全部失败使用不同文案。部分失败只重试失败对象，成功对象不能重复收到。离线显示“等待联网”，用户可以取消尚未发送的任务。已送达的撤回能力若后端不支持，不提供虚假撤回按钮。

消息默认发送到对方账号；是否展示在其相框由对方的接收范围控制，不自动向其所有设备或家人广播。

## 9. 小叙对话添加家谱

> AI对接：家谱关系提取统一为AI-20，账号绑定与权限由业务确认；操作交互遵循本文件第4节。

### 9.1 两个入口

家谱页增加“跟小叙说，添一位家人”，或直接对小叙说“把我女儿加进家谱”。进入同一对话流程，继承当前选中的参照人物和家谱ID。

### 9.2 逐步确认

例：“这是我儿子陈知远，他和沈宁有个孩子叫陈星禾。”

1. 保留原语音及转写；提取候选人物与关系，不立即写入正式家谱。
2. 显示一句理解：“陈知远是您的儿子，陈星禾是陈知远和沈宁的孩子，对吗？”
3. 信息缺失时一次只问一个问题。“沈宁和陈知远是什么关系？”不能因为两人有孩子就擅自认定婚姻。
4. 性别、出生日期、是否在世、婚姻状态不是创建人物必填，不从姓名推断。“孩子”不强迫自动变成儿子／女儿。
5. 用户修改候选后展示简明卡片：姓名、相对谁、什么关系、是否关联账号。按钮“确认加入家谱／再改一下”。
6. 确认后以事务写入人物与关系，返回原家谱并定位新增成员，提供“撤销本次添加”。

### 9.3 同名与去重

同一 accountId 已在该家谱时提示定位原人物；同名但没有账号时列出候选和关系让用户选择“就是这位／另一个人”。模糊识别“晓荷／晓禾”不自动合并。未说姓名可建立“姓名待补充”的草稿，必须明确它不是已识别账号。

### 9.4 账号关联是独立动作

新增人物可以没有账号。不得把小叙识别的名字绑定到同名小程序用户。通过邀请或账号确认建立关联，接受前为待关联；对方拒绝不删除家谱历史人物。家谱照片识别也只能建议候选，不直接认人。

### 9.5 关系一致性与危险操作

禁止自己成为自己的父母、亲子有向环、重复同一关系边。对冲突关系先提示，不能自动覆盖旧事实。离异、再婚、收养、继亲、非二元性别等关系通过明确关系类型表达，不强制二选一父母或只有一对配偶。现任／历史配偶需有效期或状态，不能用新配偶覆盖旧家庭。

“删掉某某”不直接执行：展示影响范围，要求确认；有关联账号、共同维护或后代时不能级联删除全部后代。撤销新增仅撤销本次变更集；之后有其他人编辑的节点转为冲突确认。

### 9.6 失败与离线

语音识别失败保留录音并允许手动改姓名／关系；模型超时保留草稿；用户中断回来恢复未确认候选。离线可保存家谱草稿但不宣称已同步。部分关系写入失败整体回滚，避免出现只有孩子没有来源关系的半成品。并发提交使用版本号校验。

### 9.7 亲友列表与家谱呈现

#### 9.7.1 亲友账号卡片

“家人／亲友”分段切换。亲友卡片显示头像或姓名占位、昵称／备注、关系；点击详情可发日常、修改本人备注。关系标签来自双方已确认的联系语境，不自动授予家谱编辑权。

首版有姓名搜索、关系筛选和空态；小名单不强制显示复杂筛选器。用户停用账号后保留必要的历史显示快照，但不允许继续发送。

#### 9.7.2 家谱布局

以当前长者personId为参照，纵向按代际，横向夫妻或同辈；夫妻横向连线，父母子女由明确节点或组合连线向下。线不穿过人物卡片，交叉不可避免时高亮选中人物的相关边。

默认大字局部视图定位到“我”，支持上下左右滑动；“看全家”适配整体，“回到我”恢复可读尺度。全图缩略不作为唯一阅读方式，提供大字名单视图。家庭人数增加时不无限缩小默认文字。

图中展示头像、姓名、相对当前长者的关系；详情补充准确关系、账号关联状态。亲友非家人不强行放进家谱。未知人物用占位，不凭空补齐四代。真实空家谱只有本人，加人入口可见。

全屏可作为增强，但退出保持视角；触控拖动不能误触人物。节点与名单均支持屏幕阅读器，读出姓名和关系。

#### 9.7.3 维护与共享

本人管理自己的家谱；家庭共享树需要familyId、成员角色和明确授权。亲属不是天然管理员。看家谱权限、看人物资料权限、看碎片权限、发日常权限分别判定。

允许未关联账号、已故人物和未知生卒年月。已故不自动触发账号注销；禁止自动弹出生日营销提醒。家庭关系信息只向被授权家谱成员可见，不暴露给所有学生、同事或普通联系人。

## 10. 我的、记录、来信与设置

### 10.1 我的与资料

头像、姓名居中，编辑入口明确；右上角齿轮进入设置。仅列“我的拾光／发过的日常／我的亲友”。不放“学生们熟悉的陈老师”等人物介绍，不放统计和赠礼宣传。

个人资料修改姓名与头像；头像校验、上传失败保留旧头像。建议姓名1–24字，前后空白去除。修改需服务端确认后传播到本人其他端；亲友的私人备注不会被覆盖。不可通过改姓名修改账号归属。

### 10.2 我的拾光

默认最近保存优先，卡片展示缩略图／语音标识、简短文字、保存时间和同步状态。空态“还没有留下内容”配“去留一段时光”；不放示例内容伪装用户历史。

详情可回听、看图、修改文字与标签、调整已确认拍摄日期。长者原始录音保留，修改不强迫重新录。删除二次确认并说明已同步到相框的影响；删除个人记忆与撤回已发出的日常是两件事。

下载和清缓存不得误删云端原件。分页加载、加载失败重试、离线已缓存查看均需支持。

### 10.3 发过的日常

按发送时间倒序；展示内容摘要、收件人、每人状态。多人发送汇总为一次日常，点开才看各收件人状态，避免刷出重复内容卡。

失败可修改后作为新版本发送，或使用原幂等任务重试；必须明确是哪一种。读取状态未知就显示已送达／状态未知，不用“已读”代替。清除本地记录不代表对方收件箱被删除。

### 10.4 设置与来信

设置：个人资料、更大字号、提醒、账号与隐私。更大字号立即生效、持久保存，返回不丢位置。提醒包含系统权限状态、App内开关、免打扰；未接入实际通知时原型不显示假开关。

隐私说明必须与真实采集和SDK一致；提供退出登录、账号删除申请和数据导出入口的服务端流程。删除账号需要再次身份验证与影响确认，不用前端清缓存冒充注销。

来信点击后主动展开，显示发送人、时间、内容；语音不自动播放。若支持回应，必须用户主动点击或录音确认，AI不能自动回信。原消息撤回或资产失效显示可理解状态，不报数据库错误。

### 10.5 提醒

小叙仅提醒有新来信，用户主动查看才展开内容，不自动朗读正文。锁屏仅通用提示，同封来信去重；免打扰建议21:00—08:00可配置，录音／确认发送期间不弹窗。系统通知权限与App内提醒开关分开，关闭提醒不妨碍主动查看未读。

## 11. 视觉、声音与可用性

继承小程序和当前 App 的暖白纸面、克制绿灰主动作、大字与大按钮。正文建议21—24px，主要点击区域不小于48×48，系统大字模式不截断操作。字号、屏幕阅读器及横竖屏需真机验收。

小叙使用现有小男孩透明素材，在最新回复左侧探身出现，可短暂轻晃／问候，不带矩形底色、不挡文字、不持续跳动。减少动态效果设置下停止非必要动画。录音时不让角色动作掩盖监听状态。

回复选项靠近对应消息；新回复和选项进入视口，但用户主动翻看旧消息时不强制滚回底部。长回复优先分段，不能把所有动作堆成复杂表单。

辅助信息建议不低于16逻辑像素，主操作采用大按钮，系统字号放大到200%能换行且不裁切；颜色不是唯一状态依据。页面适配真实安全区，键盘弹出后输入与操作可达；不画假状态栏。家谱提供大字名单、定位本人、屏幕阅读器与键盘替代路径。App主操作色沿用本端当前绿灰规格，小程序／相框的暖棕规范不强制覆盖本端。

## 12. 工程执行契约

客户端负责媒体、系统权限、语音输入、状态展示；Agent负责理解意图与提出结构化动作；业务服务负责权限、校验、幂等执行和真实结果。模型不得直接越过业务接口写数据。

建议动作信封：actionId、conversationId、taskId、stateVersion、source（voice／tap）、intent、entities、targetIds、confirmationToken、idempotencyKey。执行结果区分 succeeded／pending／needs_clarification／needs_confirmation／failed／cancelled。

流程：转写→区分命令与内容→解析指代／选项→权限及前置条件校验→必要确认→执行→根据真实结果回复。长耗时动作显示处理中，允许取消可取消部分；取消后迟到结果不得重新提交。重试时沿用同一幂等键。

媒体不上传到未获授权的服务；日志尽量记录意图与错误码，语音和图片不进入普通诊断日志。云端识别需明确授权与留存策略；离线仍可拍照和存本地草稿，不能假装完成云端发送／搜索。

### 12.2 服务能力

接口名称供实现协调，可调整路径但必须保留语义：

- 身份／资料：获取当前账号、更新资料、关联小程序身份、退出／注销任务。
- 资产：申请上传、分片／断点续传、提交校验、短时访问凭证。
- 碎片：创建幂等、分页查询、带revision更新、软删除、恢复、设备同步回执。
- 日常：提交收件人列表、查各人送达状态、取消未发送、重试失败收件人。
- 亲友：已授权联系人查询、修改私人备注、邀请与接受。
- 家谱：读取树及revision、生成候选、校验关系、用户确认后提交changeSet、撤销、邀请关联账号。
- 小叙：语音识别、对话、受权限约束的工具建议；写操作必须携带幂等键；外发、删除、解绑和关系变更等需确认动作另带有效确认令牌，明确保存本人记录无需额外确认弹层。
- 提醒：未读索引、通知偏好、读取内容、提交回应。

客户端不能靠隐藏按钮实现权限；服务端每次按当前用户验证familyId、personId、assetId、recipientId访问。跨端变更通过增量版本同步，离线冲突不使用无条件最后写入覆盖。

## 13. 边缘情况验收

| 条件 | 必须行为 |
| --- | --- |
| 方言／低音量／识别失败 | 显示可修改转写，重说或打字，不猜命令 |
| 多次重复“拍照” | 单次曝光锁，拍后确认，不产生连拍误操作 |
| 倒计时中说取消 | 立即终止，保留取景 |
| 录音期间切页／来电 | 停止资源占用，保留已采集内容和任务 |
| 相册有限授权 | 只列获准图片，给扩展授权入口 |
| 同时说“第二个”和点击第三个 | 原子校验当前状态，只执行一次并反馈实际结果 |
| AI朗读“确认发送” | 不被ASR当成用户确认 |
| 修改收件人后迟到的确认 | 旧版本确认拒绝，重新读出对象 |
| 网络断开／恢复 | 草稿保留；外发需可见状态，不重复提交 |
| 保存后又补一句 | 同一回忆追加更新，旧内容不丢 |
| 退出再登录另一账号 | 不泄露前账号草稿、照片、搜索与亲友 |
| 拍照成功但保存失败 | 保留内存／本地临时照片，提供重试 |
| 设备不支持语音或相机 | 明确说明，保留选图、文字与触摸路径 |
| 亲友未绑定／取消接收权限 | 禁止发送，允许换人或存为本人回忆 |
| “他说删掉这张照片” | 识别为叙述或澄清，不直接删除 |

### 13.1 完整链路

以下为正式上线要求，不是当前原型通过声明。每项均需触摸路径和语音路径分别验证，并覆盖真实设备、授权拒绝和中断恢复。

1. 首页说“记个回忆”→讲述→“帮我整理”→“保留原话”→“存下”→继续补充同记录。
2. 收到AI选项后说“第二个”执行对应动作，过期选项与歧义数字不误执行。
3. “打开相机”→授权→“换前置”→“三秒后拍”→“取消”后不拍。
4. 打开相机→“拍一张”→“重拍”→“用这张”→给指定亲友→确认发送。
5. 相册“第二张和第四张”→取消第二张→继续，预览与选择一致。
6. 亲友重名澄清→多选→移除一位→朗读全部对象→确认发送。
7. 发送前“先不发”不产生发送请求；修改内容后必须重新确认。
8. “找和学生的合影”→真实检索候选→“不是这张”→调整条件→打开正确记录。
9. 我的→语音打开已保存内容→改标题→确认→返回位置保留。
10. 家谱语音添加→确认关系→保存personId；不自动建立accountId。
11. 关闭朗读／放大字号／返回均可语音操作，不影响会话。
12. 无网、失败重试、重复确认、后台切换与账号切换满足本章。

### 13.2 数据与关系补充验收

| 场景 | 必须行为 |
| --- | --- |
| 相册／相机取消或拒绝 | 原内容保留，仍可只说话／打字 |
| 麦克风拒绝、忙碌、设备缺失 | 明确提示，允许改打字，不显示假录音状态 |
| 按住时权限返回前已松手 | 不录制、不发送 |
| 上滑取消、页面隐藏、触摸中断 | 停止音轨，无新语音消息 |
| 录音太短／静音／编码失败 | 不伪造转写，原稿保留，可重试 |
| 长录音自动截止 | 明确结束并可回听，不持续后台采集 |
| 识别结果迟到 | 不覆盖用户已编辑内容 |
| 同名人物、关系不确定 | 询问确认，不自动绑定账号 |
| 语音识别错姓名 | 确认卡可改，未确认不入树 |
| 重复添加／关系成环 | 阻止并定位问题，不破坏原家谱 |
| 修改家谱时另一端已更新 | 提示冲突，重取版本，保留候选 |
| 断网创建家人 | 本地草稿，不显示云端成功 |
| 账号邀请被拒绝 | 保留未关联人物，不允许发送 |
| 发送对象失效 | 标出失效人，其他对象经确认可继续 |
| 多人部分失败 | 单人状态清晰，仅重试失败对象 |
| 连点保存／发送 | 同幂等键单条结果 |
| 上传中杀进程 | 可恢复任务，不能产生不可追踪半条记录 |
| 空间不足 | 停止新增录制／缓存，保留已有内容，不清除用户资料腾空间 |
| 登录切换用户 | 本地私密数据隔离，不展示前一位长者资料 |
| 超大字号／小屏／横屏 | 主按钮可达，标签栏不盖内容，家谱可用名单阅读 |
| 家谱超过100人 | 按分支加载，定位本人，不能强行压成不可读微缩图 |
| 新来信发生在录音中 | 等待合适时机提醒，不打断和自动朗读 |
| 提醒关闭／免打扰 | 不主动打扰，主动访问仍可看未读 |
| 相框未联网 | App显示待同步，不声称相框收到 |
| 删除后另一端打开旧内容 | 遵守版本与权限，显示已删除状态 |
| AI不可用 | 保留录音、提供手动姓名／关系填写与确定性操作帮助 |
