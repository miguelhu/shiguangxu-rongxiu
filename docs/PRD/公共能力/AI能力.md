## 1. 产品目标与权责

小叙帮助用户表达、保存、查找和操作，产出可追溯的候选或可验证的业务动作。不补造经历，不替用户决定授权，不冒充原声，不用生成话术宣称尚未完成的保存或发送。

荣休核心包括单人表达、人物介绍、共创邀请和集体信；相框与App还覆盖日常回应、记忆、语音和操作。集体信是核心产品能力；个别项目是否允许缺信交付由总览D-03及项目模板决定，不把能力首发与每份礼物必须含信混为一谈。

项目生命周期、授权和通知见[总览与公共规则](../总览与公共规则.md)；页面业务流程见[各端PRD](../README.md)。本文件负责AI输入输出、内容规范、候选采用与执行边界。旧版本和演示实现不覆盖当前规格；新增参数建议与待定门禁明确标注。

### 2.1 不应增加模型调用的能力

日期排序、同作者连续照片拼图、标签去重计数、二维码／邀请卡绘制、生命周期通知、生日触发、回执、授权校验、内容包下载、冻结、播放翻页、搜索确定性筛选、家谱关系成环检查均是业务或规则服务。它们可由AI-19提出操作，但最终执行不由语言模型完成。

照片分类AI-14建议的“故事组”与仪式拼图不是同一对象；不能改变相框PRD第19章“最终顺序连续、同作者、同时间桶、最多4张”的规则。

## 3. 所有能力共用的内容规则

### 3.1 十条规则

| 规则 | 必须遵守 |
| --- | --- |
| R01 事实忠实 | 不新增人、事、时间、地点、身份、荣誉、动作、对话、因果和内心。 |
| R02 归属准确 | 区分作者、亲历者、被描述人、受礼者、发信人；一人回忆不变成共同记忆。 |
| R03 保留不确定性 | “约、可能、记不清”不得变成确定结论；未确认日期不入精确年表。 |
| R04 用途授权 | 处理、引用、署名、仪式、日常、礼前预览、公开分享分别校验。 |
| R05 不足与冲突 | 可短写、补问、保留差异；不以多数说法替代核实。 |
| R06 最小加工 | 原文自然可零修改；加工动作决定上限，文风不扩大权限。 |
| R07 情绪克制 | 不添加亏欠、牺牲、永远承诺；“我开心”不能变“大家开心”。 |
| R08 页面适配 | 不截断关键事实；优先分段、分屏、查看全文；标题不夸大。 |
| R09 多模态真实 | 原音、转写、整理稿、系统朗读、AI示意图分别标识。 |
| R10 来源留存 | 原件不覆盖；每份候选可回查素材修订、作者与用途。 |

上述规则来自内容规范与既有PRD；“很开心”不能无依据扩为“大家都很开心”。时间连接词如“后来”“那天”也必须有事实依据。匿名转述不能绕过内容授权。

### 3.2 加工动作与风格

- `smooth` 顺一顺语句：纠错、断句、去重复，按风格调整措辞。
- `shorten` 更简洁：保留主体、核心事件、数量、否定、条件、不确定性。
- `organize_story` 整理故事：重组单人叙述，保留事实顺序与因果，禁止补情节。
- 集体信首次生成、局部修改、追问、ASR、检索、TTS和动作执行采用自己的任务动作，不强套上述三按钮。

| 能力 | 可选动作 | 四风格选择 |
| --- | --- | --- |
| AI-01 | suggest_tags／compose_impression | 标签不展示风格；短句默认自然 |
| AI-02／04／06／07／10 | smooth／shorten | 支持；自然口述默认 |
| AI-03 | smooth／shorten／organize_story | 支持；自然口述默认 |
| AI-05 | compose_letter | 首版不强制四风格选择；默认自然、得体、克制 |
| AI-09 | smooth／shorten／change_style，范围限所选段 | 支持；保留现稿风格为默认 |
| AI-15 | compose_story | 可用四风格，素材确认不省略 |
| AI-16 | title／summary／weekly_recap | 默认客观简洁，不要求选风格 |
| AI-08／11—14／17—27 | 各自任务动作 | 不展示无意义的文风选择器 |

只在明确需要生成表达时选择风格。App可说“再口语一点”选择自然口述，语音和点击传同一枚举；聊天回复、错误提示、系统通知仍采用清楚简短的默认语气。

### 3.3 同一素材的四种文风

以下为产品标准示例，不是模型实测输出。前端每个选项下有一句说明，可展开完整示例；统一展示原素材，不能把静态例句当成用户候选。

**原素材**：李老师，刚来单位时，我不太会做方案，您帮我一遍遍修改，我一直记得，也很感谢您。现在您退休了，祝您身体健康，多些时间做自己喜欢的事。

**自然口述 `natural_oral`**：像平时说话一样，亲切、顺口。

> 李老师，我刚来单位那会儿，不太会做方案，您帮我改了一遍又一遍。这件事我一直记着，也一直很感谢您。现在您退休了，祝您身体健康，多些时间做自己喜欢的事。

**文辞柔美 `soft_literary`**：文字柔和细腻，留一点回味。

> 李老师，初到单位时，我还不太会做方案，您一遍遍帮我修改。那份帮助留在记忆里，感谢也一直在心中。如今您退休了，愿您身体安康，把更多时光留给自己喜欢的事。

**沉静大气 `calm_dignified`**：表达舒展稳重，情感含蓄有分量。

> 李老师，初到单位，不熟悉方案写作，是您一次次帮我修改。这份帮助，我始终记得，也始终感谢。如今您已退休，愿您身体健康，有更多时间从容做自己喜欢的事。

**郑重真诚 `formal_sincere`**：认真表达感谢，得体而不生硬。

> 李老师，刚到单位时，我还不太会做方案，您曾一遍遍帮助我修改。对此，我一直铭记，也真诚地感谢您。值此退休之际，祝您身体健康，有更多时间做自己喜欢的事。

沉静大气强调节奏和克制，郑重真诚强调正式致意；文辞柔美不能靠虚构风景、动作和感受形成差异。素材仅“退休快乐”时四版允许接近。

## 4. 共享候选与确认流程

### 4.1 文字编辑流程

当前草稿 → 选择适用动作和风格 → 点击生成 → 查看原文／候选 → 编辑候选 → 明确采用 → 回填草稿 → 保存或提交。采用不代表发布、发信、锁版或获得额外授权。

切换动作／风格不自动调用。重新生成基于本次输入快照，不反复润色上个AI稿；用户手改并明确作为新输入时创建新快照。每次一份有效候选，旧版本留在历史但不自动采用。

空白仅给对应静态引导；不调用不支持空输入的能力。未改动可返回 `unchanged` 并提示“这段话已经很自然，可以保留原文”。超字段上限提示精简，不能静默截断。

### 4.2 状态与恢复

| 状态 | 行为和文案 |
| --- | --- |
| idle／empty | 手写始终可用；“先写一句，小叙再帮你整理”。 |
| generating | 显示真实处理中，禁重复请求，允许取消；其他字段继续可编辑。 |
| ready／unchanged | 可对照、手改、采用或保留原文；零修改也是有效结果。 |
| needs_input | 只问当前缺少的必要信息，素材少可直接短写。 |
| needs_review | 标出问题及来源，关键冲突未解决不能进入发布。 |
| stale | 原文、来源、角色、用途、动作或风格变化后旧候选不可采用，提示重新生成。 |
| failed／unavailable／timeout | “暂时没整理成功，原文已保留”；可重试，不用模板伪造成功。 |
| cancelled | 关闭任务；晚到响应不回填、不重新弹出、不触发发送。 |

撤销恢复采用前草稿。采用后又手改，则展示将恢复的版本并确认影响。多人或跨端编辑用基修订校验，不做无条件最后写入覆盖。撤销内容操作不等于撤回已经发送的消息。

### 4.3 四类确认不能合并

1. 作者确认：这是自己的意思，以及允许哪些用途。
2. 统筹审核：核对来源、事实、用途与是否纳入当前项目。
3. 候选采用：将这份候选作为当前编辑版本。
4. 业务确认：提交、外发、发布、锁版、关系变更分别确认，不能以“生成过”代替。

本人个人记忆保存按App规格直接保存，无新增逐屏强制审核；识别不确定字段可保留未知。外发和敏感变更必须确认实际对象及版本。

## 5. 角色 数据范围与长期记忆

### 5.1 权限矩阵

| 角色／空间 | 可见和可处理 | 不允许 |
| --- | --- | --- |
| 投稿者 | 自己草稿、候选、投稿；他人明确许可的礼前片段 | 默认读其他投稿、统筹内部问题、长者私人记忆 |
| 有效统筹者 | 已提交且授权统筹审核的待审素材；获准源、候选信和审核轨迹 | 私人未提交稿；将待审素材送入AI-05；读长者健康／保险箱 |
| 受礼者 | 按拆封及用途允许的成品；公开许可的作者署名与来源入口 | 内部审批日志、争议备注、未允许的手机号及私人源稿 |
| 长者本人相框／App | 本人记忆、明确共享给本人的内容、当前会话 | 以亲属关系推导全家数据权限；把个人库注入荣休项目 |
| 现场设备 | 当前现场会话获准的冻结播放包 | 私人来信、家庭空间、健康和长期会话 |
| 服务账号／模型 | 当前任务最小授权投影 | 自行跨项目检索、决定发布、扩充授权 |

待审素材允许统筹人工看，不代表允许进入模型。模型处理许可、公开署名许可、仪式许可是不同字段；撤回任一用途需按依赖关系重新裁决。

### 5.2 Memory的三种含义

1. 临时任务上下文：仅当前conversationId／taskId，随任务和账号隔离。
2. 产品里的个人记忆记录：用户明确保存的Fragment／memoryId，可在相框与App获准范围查询。不是自动对所有AI开放。
3. 模型长期画像或跨项目Memory：本版默认关闭，不自动写入或检索。App“持续会话”不等于全量长期画像。

荣休礼只用当前项目获准内容；复用本项目历史需要所选来源和当次用途仍有效。长者App可显式搜索本人已保存记忆，但结果进入新作品／分享仍需用途校验。健康、保险箱、未拆封礼物不进入普通聊天默认上下文。

### 5.3 留存 删除与派生内容

以下为本版产品建议基线，必须与总览D-10及真实服务方案冻结后方可生产启用，不是法律保存期限承诺。

| 数据 | 建议处理 |
| --- | --- |
| 未采用AI候选 | 最后活动后7天清理正文；已采用版本随业务记录保存 |
| 临时口述／命令音频 | 转写确认后尽快删除；失败恢复最长24小时，单独说明；不能当原声祝福保留 |
| 用户明确保存的原文／原音／照片 | 账户与业务有效期内依用途保存；删除／撤回走影响确认，建议可恢复期30天 |
| 内容源及派生版本关系 | 随仍有效的成品保留最小必要引用，已撤回正文不得因审计继续可读 |
| 审批／动作／版本审计元数据 | 建议180天，默认不含原文、音频或私信正文；最终由治理方案冻结 |
| 第三方处理缓存／备份 | 需逐服务确认删除与留存能力，不能仅凭本地删除承诺已清空第三方 |

删除原文先说明受影响候选、总信、作品、搜索索引与分享；撤回用途优先阻断访问，再失效派生、缓存及索引。已冻结快照不可任意编辑，但不得借快照阻止真实授权撤销。离线设备不能保证立即清除，联网优先同步撤销；离线许可期限仍需D-10定案。

## 6. 算法与业务接口的产品契约

实际接口路径、模型、Provider、流式实现由研发决定；以下字段含义和业务结果必须保留。

### 6.1 请求与来源

`capabilityId`、`clientSurface`、`pageId`、`scene`、`variant`、`action`、`style`、`objectId`、`baseRevision`、`requestId`、`sourceManifest`、`outputConstraints`、`consentContext`。

会话任务另带conversationId／taskId／stateVersion；局部编辑带选区及受保护字段；动作执行带幂等键；需确认的动作另带确认令牌。稳定业务ID由后端读取并验证，不能信任模型输出或客户端自报的角色。

sourceManifest由服务端保存源ID、源revision、作者／亲历者、允许用途、批准状态、撤回状态和hash。模型看到的是临时源标记及必要语义角色，不一定看到真实姓名；需要引用署名时用获准显示名。来源映射必须能够由响应临时标记还原，不能仅保存一个无法定位段落的总hash。

### 6.2 响应与错误

`status`、`candidateId`、`candidateRevision`、`generatedText／segments／proposals`、`sourceRefs`、`uncertaintyFlags`、`reviewRequired`、`modelVersion`、`promptVersion`、`inputHash`、`errorCode`。

区分成功、无修改、待补充、待审核、空输出、超时、限流、无权限、服务不可用、版本过期与取消。不支持组合的action／style必须校验拒绝，不默默改成另一任务。未配置provider不能返回mock成功。

服务端在请求前、采用时、发布时、读取／搜索时分别校验权限。生成后用户失去统筹权限，不能用旧候选继续锁版。长耗时请求取消后可留审计，但不得恢复外发操作。

### 6.3 Agent动作与内容生成分离

AI-19返回动作提案，业务执行器检查当前页面与前置状态。`succeeded`、`pending`、`needs_clarification`、`needs_confirmation`、`failed`、`cancelled`不同；工具返回事实是回复的唯一执行依据。

命令语音→AI-11→AI-19；生成文字任务→对应AI能力→AI-27→候选采用；读给我听→AI-18。同一个页面可以调用多个能力，但不将ASR、润色、发送合并成未经用户确认的一步。

## 7. 交付与质量门槛

荣休核心连通AI-01—09、必要AI-11及AI-27；AI-08不请求模型。App全页面语音依赖AI-11／12／13／17／18／19／20及文字整理。相框按本端首交付与增强范围开放，不因共用编号强开未配置功能。

产品／内容核对事实、归属和表达；算法交付受控输入输出与真实评测；后端负责权限、版本、幂等及执行回执；前端交付候选、撤销、错误态与语音点击等价；测试按附录C逐项留证。无provider不可回mock成功，写作失败不阻断手写。

### 7.1 内容评分

六维使用1—5分，权重点数为：事实忠实30、任务完成20、情绪适度20、个性保留15、角色授权10、展示适配5。总分公式：`Σ(该维得分 / 5 × 权重点数)`，满分100。

- 出现事实捏造、归属错置、未经授权引用、原声冒充、私密泄漏、假执行成功等严重问题，一票否决，总分不能补偿。
- 合格：总分≥85，事实=5，任务≥4，其余各维≥3，且无否决项。
- 优秀：总分≥95，各维≥4，且无否决项。
- 总分<75不合格；其余未满足合格条件为需修改，不能作为可发布稿。
- 机器筛查只作辅助；事实、归属和授权必须结合源和业务记录核对。人工原文已自然时“无需修改”可以合格。

评分用于内容能力；ASR另测关键实体／否定识别，检索测授权过滤与相关性，Agent测动作正确性及误执行，TTS测音频和可懂度。不能给发送接口一个文案分数来证明成功。

## 附录A：能力卡（按编号查阅）

各卡短稿长度是建议目标，不是最低字数；字段硬上限按本端规格。来源、用途、候选及失败规则对所有端一致，页面入口见附录B。

### AI-01 印象建议与成句

- 触发：C11选择标签时主动请求；或作者提供印象关键词，希望连成短句。
- 输入：当前作者已选词／自写评价、明确关系；不使用其他投稿猜“大家印象”。
- 输出：可选标签列表或单人印象短句，两种variant分开；用户逐项选取，不自动填满5个。
- 约束：标签2—12字、选用1—5个；标签长度沿用小程序建议；短句15—45字为软目标。无词无例时显示配置词库，不生成确定评价。
- 确认及降级：作者采用后提交；离线用词库／手输。统筹与相框只聚合获准标签和真实去重人数，不重新生成人格。
- 验收：输入“认真、细心”可得“做事认真细心”，不能变成“从不出错、一生无私”。

### AI-02 照片文字说明整理

- 输入仅作者写下或确认的转写文字；本能力不接收图片像素、EXIF、文件名、上传顺序或其他照片上下文。
- 输出当前照片的文字候选。小程序每卡硬限制100字；内容目标15—60字不是最低字数。其他端按对应字段限制，不套小程序100字给所有作品。
- 无描述时引导补一句；图像理解归AI-14，确认后叙事归AI-15，不能从这里隐式触发。
- 作者采用并保存；更换照片后提示核对说明，候选关联旧照片时失效。服务失败保留文字和照片。
- 验收：同一原文配不同图片，请求素材仍只含原文；不能因图像不同写出身份、年代或心情。

### AI-03 单人故事整理与改写

- 输入：当前作者的讲述、已确认转写、选中原文片段及明确允许的本人资料；整篇／段落范围明确。
- 输出：正文候选，标题需要时调用AI-16；保留第一人称或既有叙述视角。小程序上限2000字沿用本端建议，120—300字仅是短故事目标。
- 整理故事动作可去赘词、分段、重排已知顺序，不添加天气、对白、心理和结局；不能“越写越长”证明效果。
- 相框和App修改自己的作品；别人投稿仅有阅读权时不能覆盖作者原文，可另写本人补充。保存新revision不改旧仪式快照。
- 失败可存原话；一句素材也可保存。验收：一次帮助不能变成“每次”，局部编辑不得修改选区外正文。

### AI-04 个人祝福润色

- 输入当前作者已有祝福及明确称呼关系；输出一段候选。短20—80字、长80—200字为软目标，小程序上限200字沿用本端建议。
- 仅smooth／shorten，四文风可选；不自动扩写感谢、经历、承诺。原句自然可保持。
- 空白或仅称呼转AI-08；录音祝福仍保存真人录音，改写文字不能冒充原声字幕。
- 作者采用后独立提交；相框／App仅在真实个人祝福用途时共用AI-04，普通回复用AI-10。
- 验收：“有空回来喝茶”不能变成“我们永远铭记您的伟大奉献”。

### AI-05 多人集体信正文生成

- 角色：当前有效统筹者。人工模式先完成照片、故事、祝福及标签用途检查；每条素材具备作者用途许可和统筹纳入批准。
- 输入：本项目批准且未撤回的文字、确认人物资料和准确转写；不读名单代替投稿、不读私密草稿。模型投影保留临时来源标记、必要角色与亲历归属，内部ID和完整审批轨迹留在后端。
- 输出：正文段落及各段来源映射、待核项。固定标题、称谓、收束祝愿模板和署名由产品模板／统筹确认。正文可有素材支撑的祝愿，不生成双重落款。
- 可按主题重排，不以职位权重排序；不强求保留提交时间顺序。默认无小标题；主题结构不改变亲历归属。“我们”限实际授权联名范围；“大家都经历过”须有逐项依据；组织全体署名另需授权。
- 180—320字为短版目标，素材少就短写；只有一位作者的素材时按个人寄语明确身份，不假称多人共同经历。无有效主体素材返回不足，不凑信。是否可无信锁版由项目模板及D-03决定。
- 候选→统筹核对来源与署名→确认→整体预览→锁版。重复生成先保留人工稿。来源修订／撤回后候选与确认失效，不能只改显示文字绕过。
- automatic系统整理仍为D-01待决策分支：未冻结授权和发布策略前不得开启无人审核发布，不用AI评分自动批准素材。
- 验收：甲讲留饭、乙讲改方案，不能生成“我们每个人都吃过您留的饭”；导入100人名单不等于100人联名。

### AI-06 已有人物介绍整理

- 统筹在I02编辑已有介绍，输入本人录入／已确认的人物文本，输出欢迎页可用简介候选；300字以内沿用统筹规格建议。
- 姓名、出生年月、单位、任职、荣誉等结构化事实不允许模型改字段；空白保留可选空态，不按名字补履历。
- 简介可smooth／shorten及四文风；称谓得体，不将“认真”拔高为“行业奠基人”。
- 统筹采用后保存项目资料，C00消费保存版本，不重新生成。仪式模板开场不是此接口的空白起稿能力。
- 验收：介绍里“曾在某单位工作”不补职务或工作年限；人名修改须人工事实字段操作。

### AI-07 邀请寄语润色

- 首期 `co_creation`：统筹G01邀请亲友投稿。输入仅已有邀约草稿和必要称谓；输出可编辑寄语。
- 二维码、链接、截止、项目名、主办署名由结构化模板拼装，模型不能生成／改写；空白直接用模板。
- `gift_delivery` 为独立接收礼物邀请场景预留，当前不用它替代收集结束或拆封通知；启用时仍共用AI-07但独立模板、输入投影与回归。
- 采用只更新邀请草稿；生成海报不等于转发，系统不得自动发通讯录。
- 验收：投稿邀请不写“礼物已为您做好”；后端截止更新后旧海报落地读取新阶段，不由AI决定是否还能提交。

### AI-08 祝福空输入起笔

- C14空白或仅称呼时显示2—3条静态起笔模板，支持换一批；模板版本由内容配置管理，不建立生成式模型请求。
- 点选只填入可编辑正文；已有非空正文时必须明确替换影响。自行写好后再用AI-04。
- 关系仅选择得体称呼，不预设被照顾、共同旅行等经历。录音旁的说话示例也是静态提示，不冒充转写。
- 验收：点模板不会提交、不会产生模型费用；不在总信、邀请页乱用个人祝福模板。

### AI-09 集体信局部编辑

- 仅有效统筹者编辑AI-05的未冻结候选。选定paragraphId或明确文本范围，输入该段、必要邻段只读上下文和该段允许来源。
- 允许精简、顺句、调整文风；不默认接受整篇自由指令。输出局部补丁与差异，选区外不可修改。
- 称谓、署名、来源标记、争议提示和AI标识由系统保护，不能被文本指令删除。需要改事实先修订来源再重生成，不能仅“润色”修事实。
- 采用形成新信件revision，之前确认失效；支持撤销，撤销后仍重新核对权限和来源。锁版后只能新建候选版本，不改交付快照。
- 来源审批、角色或基修订变化则拒绝应用；可保留本人编辑文本。无有效选区提示选择，不默默改整篇。
- 验收：改第二段不动首段与落款；“删掉AI标识”指令不生效；多人同时修改不覆盖。

### AI-10 日常近况与回应润色

- 小程序M01、相框R04／S08愿望已有文本、App日常／来信回应共用。`scene`区分近况、回应、愿望，不能把私人愿望当外发信息。
- 输入本人当前草稿；回应可附本人有权阅读且明确用于回复的来信最小片段，不自动拿全家历史。模型不选择收件人。
- 输出同意图候选，四风格可选；愿望和回应不添加计划、情感承诺或已完成状态。
- 空白回应给静态“看到了，谢谢你”等可编辑建议；若用户想表达其他意思，需自己说，不因有原信就替用户自动表态。
- 采用后另行确认保存／发送；多收件发送仍逐人授权与真实回执。失败保留原稿。
- 验收：对方发旅行照不推断用户“十分想念”；AI建议按钮不直接发送谢谢。

### AI-11 语音转文字

- 三端共用识别能力，区分 `dictation` 字段口述、`original_message` 真人音频、`interview` 访谈、`command` 操作语音。音频用途不串用。
- 输入有授权的实际音频及最小专名词表；输出逐段转写、不确定片段与时序，不生成润色故事。
- 小程序字段转写需确认再填入，原音默认不作为祝福提交；App操作语音按AI-19理解执行，不每句都弹转写审核。创作原声保留关联。
- 不清姓名／方言需重说或修改；无声、失败、权限取消不伪造文本。迟到识别不覆盖手改。
- 持续监听必须用户主动开启，前台可见，后台／锁屏／换账号停止；TTS不能回流成确认命令。
- 验收：口述说明与原声祝福分开；转写失败仍可保留真实原音或手写。

### AI-12 对话理解与回忆追问

- 输入当前任务会话、用户主动提供的素材与获准主题；输出简短回应及至多一个必要追问，可附2—3个当前有效选项。
- 小程序默认关系题库仍为规则服务；主动追问才调用本能力。相框访谈、AI日记和App连续聊天用不同scene，共享保真规则。
- 不预设用户亲历他人故事、不按固定人生模板追问完成度；可跳过、不记得、暂停。不因未讲心情而强制补“感动”。
- 对话不自动保存作品、发信或变更家谱；有操作意图交AI-19。已保存回忆继续补充需明确memoryId，新主题用新taskId。
- 无图像能力时只能说“照片已添加”，不能假称看懂细节；若需要图像内容，需独立授权AI-14。
- 验收：用户只说“她帮过一位同事”不能问“她帮你的那天是什么时候”；保存成功后可继续聊天。

### AI-13 内容事实与标签提取

- 从本人明确文字／已确认转写提取人物称呼、时间精度、地点、事件、主题、用户已表达情绪，每项带证据片段与待确认标记。
- 输出候选标签／事实，不等于正式人物绑定或确定日期；“女儿”不能自动变成同名账号。日期建议需确认，上传时间不作事件时间。
- 用户可删改、保留未知，缺字段不阻止保存。家谱持久关系由AI-20单独确认。
- 审核通过的元数据可供AI-17筛选；未确认模型标签只能做候选线索，不以确定事实展示。
- 验收：“大概2010年在杭州”保留大概，不能补2010-01-01；从语气不诊断情绪。

### AI-14 照片分类与成组建议

- 输入明确授权的选定照片、作者、已有确认元数据和可选文字。图片/OCR/视觉特征是否上传第三方由独立用途许可控制，不能沿AI-02默认取得。
- 输出候选组、成员ID、主题、可见物标签、依据、冲突与无法判断项。人物名、亲属关系、确切年代、地点、情绪不能仅凭画面确定。
- 用户接受／拒绝／编辑／拆组／合组后应用；支持撤销，保留每张原图与投稿作者。当前用途不允许的照片不能进入批次。
- 按“同事件”的判断不足时只作主题集合；模型聚类不能覆盖仪式拼图或手动排序。相框相册可复用同能力，空间由本人授权，不读取荣休项目后台。
- 标题可为整理标签，生成正式故事必须另走AI-15。批量应用排除冲突和未知项。
- 验收：不同作者同一图片保留两份投稿归属；无法识别不强分类，低置信组不自动成故事。

### AI-15 已确认照片素材成故事

- 用户主动选择已确认组及文字事实，核对人物、事件和可知时间后请求。只有照片无叙述时不能从视觉标签编历史。
- 输出正文候选和段落来源，可带标题；多作者材料逐段归属，不伪装单人亲历或全部共同经历。
- 每次只处理指定组，少素材短写；缺事件则提示补一句。四文风不改变事实来源要求。
- 有权作者／统筹采用后独立保存新故事，应用照片组不自动创建故事，锁版仍另行处理。
- 验收：合影不能推出“获奖庆功”；无确定时间不生成精确年表节点。

### AI-16 标题 摘要与周报

- variant分别为title、summary、weekly_recap；输入明确的已授权正文集合及输出用途，返回摘要和逐条来源。
- 标题建议6—16字、相框单屏摘要60—120字；只是软目标，不损失否定、人物和关键因果。全文入口常在，用户可不采用摘要。
- 周报由业务服务指定时区、起止区间及实际可见来信／回应；计数由数据库算，模型只整理文字；无内容不生成“大家关心你”。
- 本版方案：私人周报可自动形成标记为AI整理的只读摘要，AI-27失败则退回原文列表；分享需逐项用途许可与本人确认。不得含未拆封礼物、保险箱或健康资料。
- 投稿看板摘要只使用作者许可的预览片段，需作者确认；不得复用私人周报作为公开看板。
- 验收：本周新上传旧照片写“本周收到旧照片”，不能写成“本周参加了活动”；删除来源同步失效摘要。

### AI-17 授权记忆语义检索

- 用户发问或筛选；检索前服务端限定账号、空间、项目、用途及未拆封状态，不能先跨库召回再让模型过滤。
- 返回真实recordId／assetId、匹配依据、片段与可用动作；无结果明确无结果。自然语言可解析为人物、时间、地点、主题，疑义澄清。
- App搜索本人可访问记忆；相框只搜索本空间允许内容。荣休后台不得默认搜索长者私人记忆。分享搜索结果再次核权。
- 普通标签筛选无需模型；AI-17不可把生成图片或固定案例冒充命中。未知时间不能匹配为已确认年份。
- 验收：未拆封、撤回、别的账号和保险箱资料不出结果或摘要；“找学生合影”无命中不返回默认照片。

### AI-18 系统朗读

- 输入用户正在阅读的获准正文及其revision，不自行生成新文案；输出系统语音或原生TTS播放流。
- 明示系统朗读，可停止、暂停、续读、调整音量；不得克隆参与者或长者声音冒充本人。原声播放是普通播放器，不调用TTS替代。
- 切页、撤回、失去音频焦点、开始录音时按播放器契约停止／暂停。新来信不自动读正文；关闭自动朗读仍可主动点读。
- 离线有授权缓存或本地TTS才可播，否则保留文字。已改正文使旧朗读缓存失效。
- 验收：朗读中用户说话先停播；朗读“确认发送”不被当用户指令。

### AI-19 页面操作 Agent

- AI只提出意图和结构化动作；客户端提供当前可执行动作清单，业务服务负责鉴权、确认、幂等执行，真实回执后才答复完成。
- App全部自有页面必须语音／点击同路：导航、相机、镜头、倒计时、相册选择、文本修改、亲友选择、保存、发送、记录、家谱、设置。不能仅实现聊天页。
- 输入pageId、taskId、stateVersion、当前选项ID、可执行动作及最小上下文。口述正文与命令先分流，“他说删掉照片”不执行删除。
- 只读导航与可逆字号设置可直接执行；保存本人内容依据明确保存指令；发送、删除、解绑、共享、家谱变更需明确对象／范围和确认。系统权限／验证码／支付不由Agent绕过。
- “第一个”只对应当前有效suggestionSetId；多个组选项、重名、指代不清先澄清。“好的”不作为外发确认。点击与语音共用幂等键，过期stateVersion不执行。
- 相机／麦克风并行须原生真机验证；系统相册不可被Agent控制，需App自有获授权选择页；后台不拍照／不监听。相框动作按已注册功能开放，不因共用编号假装具备App所有硬件。
- 验收：仅服务端接受不称已送达；部分失败只重试失败对象；收件人或正文改变使确认令牌失效；取消后迟到响应不提交。

### AI-20 家谱人物与关系提取

- 用户明确“加家人／改关系”时，使用指定familyId、参照personId、本人话语和必要有权访问的已有关系。
- 输出人物与关系候选、同名候选、缺失和冲突；不能由同名推账号，不能由有共同孩子推配偶，也不从姓名推性别。
- 一次一个必要澄清，展示关系确认卡后提交事务；关系成环／重复边由业务规则校验，整批失败回滚。账号关联独立邀请与接受。
- 相框无编辑权只读，不给AI写入口。撤销仅本次changeSet；已有后续编辑时走冲突处理。
- 验收：输入“儿子陈知远和沈宁有个孩子”只建明说关系，先问沈宁与陈知远关系；不自动声称配偶。

### AI-21 AI示意配图生成

- 输入用户主动提供的描述、获准参考图及用途，输出独立衍生文件、生成方式与引用来源。
- 新图永远标为“AI示意图”，不能放入原始照片记录，不作为经历、人脸身份或历史年代证据；跨端导出／分享保留标识。
- 先预览、再采用到作品；不替换原图。不在无素材情况下生成受礼人照片作为荣休封面。
- 失败不返回固定素材伪装成结果。验收：更换配图不更改真实故事事实，撤销恢复原图片引用。

### AI-22 原图修复

- 输入选中且允许处理的原图与修复目标，输出标记“修复版”的新资产、处理记录和原图对照。
- 去噪、清晰化不能宣称还原未知历史细节；改脸、补人、补背景须归生成式衍生并明确提示，不作为保真修复悄悄执行。
- 本人确认采用，原图可恢复；算法不可验证细节时说明局限，不自动覆盖整库。
- 验收：修复后原文件hash不变，衍生图不供人名／亲属关系的确定判断。

### AI-23 健康资料结构提取

- 专项开启后，输入本人单独授权的报告图片或健康口述；输出项目、数值、单位、记录时间及对应证据区域／片段，不生成诊断。
- 图片OCR与饮食图像候选分variant；饮食照片只能给可核对食物候选，不把估计摄入量当已测值。
- 识别不清保留待确认，用户核对后才写健康记录；任何普通聊天不自动变成打卡或健康记录。
- 健康数据分区存取，不进入AI-05、普通AI-17索引、周报或礼物包。失败保留手录。
- 验收：单位、日期缺失不自行补；文字识别成功不等于医学结论成立。

### AI-24 健康信息解释

- 专项关闭默认值；须明确内容来源、更新机制、风险处理和责任流程后开放。此PRD不提供诊断、处方或治疗规则。
- 输入本人明确授权且确认的资料及问题，输出来源可追溯的通俗解释、信息不足提示；不能假装医生、替换实际医嘱或给无依据个人风险结论。
- 高风险情况转既定人工／联系流程，不能说已通知家人或已呼叫救援；联系动作按AI-19及实际渠道结果处理。
- 医生／中医外观角色不扩大数据许可；无来源／服务失败不退回固定诊断。验收必须由专项内容与测试负责人签收。

### AI-25 出行信息与行程建议

- 输入用户提供目的地、日期、偏好和必要约束；经允许查询实时来源，返回标注来源与查询时间的可编辑建议。
- 天气、营业时间、费用、名额不可凭模型记忆或固定案例回答；查不到明确未知。位置授权独立，不自动上传精确坐标。
- 建议不等于订票、支付、报名；外部操作仍需相应业务确认。失败可留用户计划草稿。
- 验收：切换目的地后旧天气候选失效，展示示例不能称真实查询。

### AI-26 认知观察辅助

- 当前仅登记，生产关闭；需独立适用范围、有效性依据、本人同意、专业复核、误报处理和共享授权专项。
- 普通聊天、记录次数、忘记年份、未打卡均不得直接输出疾病或风险评分，不自动通知家属。
- 尚无专项时仅保留普通自愿记录或隐藏评估入口，不显示固定“正常／异常”。不把禁用本能力误解为禁用日常聊天。
- 验收：无评估授权不产生评分；后台资料不足不补假指标。具体评估指标不在本版编造。

### AI-27 内容质量筛查

- 输入本次来源投影、候选、任务、规则版本；输出可定位证据的问题列表、严重级别及人工复核需要，不产生发布权限。
- 确定性部分检查来源ID、长度、选区、受保护字段、授权和版本；语义部分辅助检查事实新增、错归、情绪与风格。
- 检测失败、未完成或信息不足不能被前端映射为“审核通过”。已发现严重问题拦截该候选，可保留原文手动修改。
- Dify自评分不能替代人工复核；既有测试中的高分归属漏检必须加入固定回归。验收与阈值见第7章及附录C。
