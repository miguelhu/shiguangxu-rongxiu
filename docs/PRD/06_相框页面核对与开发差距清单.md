# 相框页面核对与开发差距清单

本文件是《05_拾光叙相框完整产品PRD_V2》的实现核对附件，不是产品页面文案。用于区分现有原型、正式产品要求和待开发事项。核对基于当前部署页面及本地对应代码，不是对真实账号、短信、硬件或服务端接口的验收。

## 1. 参考项目与核对方式

| 内容 | 实际来源 |
| --- | --- |
| 当前日常相框 | `ai-frame/prototype/showcase/src/router/index.tsx` 与 `src/pages/Frame*.tsx` |
| 日常相框在线入口 | `https://shiguangxu.miguelhuchen.space/photoframe/#/frame` |
| 仪式播放 | `rongxiu-code/web/src/v6/CeremonyFrame.tsx`；拆分工程中同名组件 |
| 仪式／日常展示切换 | `rongxiu-code/web/src/v6/Frame.tsx` |
| 展示链路绑定页 | `rongxiu-code/web/src/v6/LifecyclePages.tsx` 的 `Activate` |
| 原规则基线 | 产品总PRD、小程序PRD、统筹PRD及原相框专项 |
| 当前统一视觉 | `rongxiu-code/web/src/v6/frame-theme.css` 及拆分端副本 |

已逐路由打开相框主体及详情页，读取可见内容与按钮；检查对应组件的状态、跳转与动作实现。动态详情使用一条具体记录核对结构，并不等于穷举所有素材记录。原型支持多个展示版本，本次以默认新版日常相框为基准；旧版布局不作为第二套正式产品。

本次浏览记录包含37个相框页面／路由组合，并补查14个状态（未完成创作、具体故事、活动详情、健康记录分类、家谱和七个仪式章节）。未进行真实注册、短信、支付、医疗或通知服务测试；上述能力的缺口结合代码判断。

本地核对材料位于 `output/frame-prd-audit/`：页面截图、`pages.json` 页面文字和按钮清单、补充状态记录。它们是研发核对证据，不是应当放进正式产品的固定案例。

## 2. 先解决的主链路断点

| 优先项 | 当前证据 | 开发目标 |
| --- | --- | --- |
| 登录与身份统一 | 日常 `/frame/bind` 比较本地预填6位码；展示绑定页使用演示二维码与固定验证码 | 使用真实账号、设备、受礼者、礼物资格模型，扫码和手机最终落同一绑定服务 |
| 仪式先后顺序 | `Frame.tsx` 初始显示日常 iframe，另有仪式切换按钮 | 正式首次路径由授权与拆封状态驱动，先待拆封与仪式，再日常 |
| 结束出口 | `CeremonyFrame.tsx` 结尾只有“再看一遍” | 添加明确“进入我的相框”，写入真实过渡状态，关闭当前音频 |
| 断点续播 | 播放组件的章节和播放状态以本地组件状态为主 | 项目＋版本＋章／项保存，重启能继续且不重复首次事件 |
| 身份贯穿 | URL场景和固定数据参与决定内容；部分子页有默认旧数据回退 | 所有查询以授权受礼者ID为根，不存在即空态／无权限，不读取其他人的资料 |
| 资产落位 | 仪式和日常消费不同素材结构，存在跨窗口载荷桥接 | 服务端资产引用统一，冻结版不变，日常索引可增量更新 |
| 真正回应 | `FrameElderReplyPanel.tsx` 录音使用构造的静音WAV，部分发送为提示占位 | 真实录音、上传、发送、去重和发送者端已回应闭环 |
| 设置生效 | 轮播值主要存组件状态，检查更新为固定提示 | 设置持久化并被主页读取，更新有真实版本与失败状态 |

## 4. 内容一致性问题

以下为此次实查到的原型问题，需要独立任务修复；本次交付PRD没有同时修改这些页面代码。

1. 陈老师场景的家庭空间人物头像与部分动态内容来自不同资料集，周报仍有旧家庭案例。
2. 时光碎片和留声机仍有旧人物的内容；相册的一些新素材已正确切换，但通用详情路由可能仍取默认项。
3. AI日记仍出现旧称呼和固定日期；AI角色里的预填示例不能当真实聊天历史。
4. 故事详情在无匹配故事时可能回退默认故事，原始参数与显示内容不一致。
5. 保险箱的未解锁界面仍可看到部分标题与说明；正式产品不应如此。
6. 现有故事包含亲友共创、点赞和评论表现；正式荣休礼相关交互应按主PRD的受控补充与长者回应处理，不能直接全量开放讨论。
7. 日常相框部分深层页面仍有绿色按钮／旧字体。完整视觉一致性验收应覆盖所有详情和弹层，不能只以主页与仪式配色判定完成。

统一修复原则：删除“找不到就拿第一条／另一个场景”的跨人物回退；查询失败显示无数据或无权限；展示固定演示数据只能存在于明确隔离的演示环境，不能进入正式产品包。

## 5. 建议实施顺序

1. 统一账号、受礼者、设备、资格与内容包模型，完成 A01—A10。
2. 连接待拆封、七章、结束页、日常主页和重播；补齐进度与幂等事件。
3. 统一日常资产索引、人物与来源，清除跨案例回退。
4. 完成收件与长者真实回应，串联小程序消息回执。
5. 完成设置、隐私、缓存、重置和异常恢复。
6. 逐页补齐记忆创作与书房；对扩展服务按可用性和正式上线条件分批接入。

每一批都应能独立验收。不要先铺所有菜单，再依靠未接通的假成功串成表面闭环。
