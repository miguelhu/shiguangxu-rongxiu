# 荣休礼相框与仪式端 PRD

版本：1.0。公共规则见 [产品总 PRD](01_荣休礼产品总PRD.md)。本端消费经确认的内容包，负责安全开启、仪式呈现和礼后持续收礼，不用播放端重新推断事实、授权或作者关系。

## 1. 使用场景与设备职责

| 场景 | 目标 | 边界 |
| --- | --- | --- |
| 相框首次使用 | 安全绑定账号、设备与礼物 | 未确认资格不展示人物资料 |
| 荣休仪式 | 集中播放已确认版本 | 不混入现场新投稿，不用职业年表替代照片故事 |
| 家中拆封 | 用户自主打开并阅读 | 不因绑定就自动播放或提前通知共创者 |
| 现场大屏 | 受控播放仪式许可版 | 不照搬仅私人许可的相框包 |
| 日常相框 | 接收新近况、播放照片、查看与回应 | 不依赖筹备统筹者永久审核 |
| 网络不佳 | 继续使用已验证的本地内容 | 不把离线当实时同步，不宣称撤回即刻生效 |

相框以触摸为基础交互；既有语音能力可增强导航和回应，但首版功能不能只通过语音才能使用。具体硬件、分辨率与系统版本需研发确认。

## 2. 未绑定欢迎与绑定 F00— F04

### 2.1 未绑定页 F00

只展示拾光叙 Logo、品牌简洁说明、真实绑定方式，以及少量通用产品内容说明。不得出现受礼者姓名、头像、单位 Logo、私人祝福、共创名单或某项目成品。

推荐布局：品牌位于上部；中心左侧“微信扫一扫绑定”的实际设备绑定二维码；右侧手机号与验证码绑定入口；底部简洁产品说明，如共创仪式、日常照片、原声祝福。不同尺寸适应上下排列，重点是绑定不是广告墙。

二维码为实际短期设备会话，不是随机无业务关联图片。码内只含不可猜测的会话凭证及必要路由，不含手机号、生日、素材、永久激活密钥。到期明确刷新，扫码手机显示这台设备的最小校验信息。

### 2.2 微信扫码 F01

1. 手机进入小程序，登录真实账号。
2. 验证设备会话仍有效、尚未被占用，校验领取资格或输入实际激活凭证。
3. 展示拟绑定设备与允许披露的领取信息，用户确认。
4. 服务端原子建立 DeviceBinding，设备取得成功结果。
5. 只有绑定与领取均成功，设备才读取该人物和项目可见资料。

别人拍下二维码并不因此可以领取礼物。若需本机确认，展示手机与设备一致的确认码／设备尾号，由用户核对；具体绑定协议归安全设计，不将 UI 点击当验证。

### 2.3 手机号验证码 F02

字段：手机号、验证码、获取验证码、确认绑定。号码与验证码按实际服务校验，发送间隔、有效期、失败次数与风控策略生产配置。

验证码正确只能证明号码控制权，还需真实领取资格：已授权接收账号、有效激活凭证或组织交付关系确认。没有资格不给出其他人礼物列表，不允许通过搜索姓名领取任意项目。

输入错误、验证码过期、服务失败、账号无资格、设备已绑定分别给出可理解提示。验证码不可记入普通日志；重试不创建重复绑定。帮助者使用自己的电话时必须明确最终受礼账号，不能默认为帮忙人永久收礼。

### 2.4 已绑定与包未就绪 F03

可以在权限内展示受礼信息和真实准备状态，继续下载、校验或重试。此时 `device_bound` 已成立而 `gift_opened` 尚未成立；不推送“已经打开礼物”。

若多份礼物可领取，选择列表仅包含本账号真实有权的项目，名称与交付状态明确，不靠固定案例切换。

### 2.5 换机、解绑与离线首次使用

换机重新校验领取授权，原绑定变更留痕。出厂重置清理本机私有缓存和密钥，不能保留上一个人的照片。设备丢失后可撤销访问并停止新同步；完全离线设备无法保证立即删除。

默认首次绑定需要联机确认。本版可提供已履约设备的签名离线开启能力，但必须有安全设计与领取证明，属于 D-09／D-11 决策，不能用“本地已有文件”直接绕过首次授权。

## 3. 正式打开 F05

绑定成功且冻结包完整、安全、许可有效后显示实际礼物开场入口。用户主动点“打开这份礼物”，验证当前允许版本并开始正式开场。

`gift_opened` 的本版方案：正式开场成功呈现后记录项目首次正式打开事件，而非二维码扫描、手机号验证、进入欢迎页或下载成功。`ceremony_started`、`ceremony_completed` 独立记录播放行为。

同项目第一次打开只产生一次共享业务事件；重播、退出再进、另一台已授权设备打开不重复发正式通知。离线打开记录本地待同步事件，联机幂等提交，以实际播放时间与服务端收到时间分别保存，不伪装实时通知。

通知服务读取项目设置及参与者分享资格，发送已授权最终成品；播放端不直接向每个参与者调用微信消息接口。事件最终定义需依总 PRD D-07 定案。

## 4. 成品七章

| 顺序 | 章节 | 内容和动作 | 缺内容时 |
| --- | --- | --- | --- |
| 01 | 开场 | 受礼者称谓、封面、荣休主题、主办署名／Logo | 缺封面用品牌布局，不虚构人像 |
| 02 | 大家眼中的你 | 获准关系概览、印象标签、真实参与人数 | 无标签／关系图则略过对应模块 |
| 03 | 一起走过的照片 | 已确认顺序、单图／拼图、日期、署名、短描述 | 无照片跳过，不加素材图冒充投稿 |
| 04 | 几个重要故事 | 实际完整故事及作者，分屏／滚动可读 | 无故事跳过 |
| 05 | 大家写给你的一封信 | 已确认集体信，正文与获准署名 | 人工版按信门禁处理；自动例外依配置，不捏造信 |
| 06 | 大家的祝福 | 文字卡／气泡、原声可播放，作者可识别 | 无祝福跳过；有声音无文字仍可用 |
| 07 | 下一程 | 从容生活的收束、主办署名、日常使用入口 | 通用收束可用，但不能替作者承诺 |

完整模板七章不等于每个项目强凑七章。默认成品至少开场＋有效主体内容。空章不显示“暂无内容”长时间停留，也不填系统生成的假回忆。

关系概览不列手机号、精确生日或私人关系备注。主要关系方向按“某参与者是受礼者的什么人”解释，不能把 student 标成“受礼者是参与者的学生”。

故事和普通祝福不同呈现：较长故事独立阅读，普通祝福多条气泡逐步露出。以表达类型区分，不以职级、单位或关系权重决定谁更重要。完整故事仍可按统筹确认顺序呈现。

## 5. 播放控制与视觉

### 5.1 基础控制

默认手动浏览，用户可以上一章、下一章、章内上一项／下一项、暂停、重新播放和返回日常。自动播放是明确可选择的模式，暂停后不继续在后台快进。

每章有可读位置指示，如照片组 3／8；指示不画职业履历横轴。滑动、按钮与遥控输入若支持，应触发同一实际导航状态。

### 5.2 Memories 式照片动效

用慢速轻微平移／缩放、柔和淡入淡出、图组切换营造回忆感。动效作用于媒体显示层，不改变日期、顺序和内容。

本版建议：单图缓慢缩放上限约 1.05 倍，拼图在进入时整体显现，不让 4 张各自疯狂移动；切换淡入淡出约 0.6—1 秒。单图自动停留建议至少 8 秒，拼图至少 12 秒；字多或用户阅读时延长，具体数值需要真实设备可读性测试。

减少动态模式取消平移缩放，保留静态排版和必要切换；自动播放可随时停，不自动恢复已暂停的声音。

### 5.3 排版

延续品牌温暖浅底、柔和绿色、少量金色的风格，仪式可用深绿色与高对比文字。字号与间距以长者实际阅读距离验证，不只照搬手机文字尺寸。

主办 Logo 适度展示开场与结束，不压住受礼者照片。横图、竖图、合影、旧照片有各自适配；保留看完整原图入口。图片背景可用原图模糊延展，不能用生成边缘冒充原始历史影像。

## 6. 照片时间模型与默认排序

### 6.1 保存字段

| 字段 | 含义 |
| --- | --- |
| photo_id / fragment_id | 稳定素材 ID |
| author_user_id | 实际投稿账号，不用署名判断是否同作者 |
| year / month / day | 已知值与空值；禁止给未知补 01 |
| precision | unknown、year、month、day |
| time_source | 作者填写、作者确认 EXIF、授权纠错 |
| time_confirmed | 是否已被明确确认，可附确认人 |
| submitted_at | 稳定排序兜底，不显示成拍摄时间 |
| presentation_position | 统筹确认后的展示位置 |
| source_revision | 素材文字／日期／授权对应修订 |

### 6.2 时间来源优先

作者确认的填写或纠错时间优先于未经确认 EXIF。扫描旧照片的 EXIF 常为翻拍日期，不能自动当老照片年代。聊天转存图片的文件日期同样不是可靠拍摄日期。

相框只读取锁版确认时间，不临时运行 AI 猜测照片年代。照片完全未知时间仍可展示，标注未知，不排入虚构年代。

### 6.3 不同精度的稳定排序补充方案

明确要求是从早到晚、未知靠后；不同精度如何穿插需要可实现的补充算法。本版建议使用“排序边界”，只计算排序，不补写或展示假月日：

1. day：以真实年月日为排序边界。
2. month：以该月起点为计算边界，显示仍只到年月。
3. year：以该年起点为计算边界，显示仍只到年份。
4. 同边界时，低精度先于高精度；随后按提交时间、稳定 photo_id 排列。
5. 完全未知放已知时间后，按提交时间、photo_id 稳定排列。

年精度与该年中后期照片的真实先后无法证明，因此把“该年某个时间”的照片放该年开始处只是编排约定，不能在界面声称它确切早于其他照片。统筹者可以拖拽修正呈现顺序。

示例默认顺序：

| 素材 | 作者确认时间 | 计算位置 | 用户看到 |
| --- | --- | --- | --- |
| P1 | 2015 年 | 该年组开头 | 2015 年 |
| P2 | 2015 年 3 月 | 该月组开头 | 2015 年 3 月 |
| P3 | 2015-03-02 | 当日位置 | 2015 年 3 月 2 日 |
| P4 | 2016-01-01 | 真实日位置 | 2016 年 1 月 1 日 |
| P5 | 不记得 | 已知组之后 | 时间待补充 |

该不同精度排序约定作为 D-04 配置的一部分验收。不可一端年精度放年头、另一端放年末导致预览与相框不同。

### 6.4 手动顺序

工作台先生成默认顺序，再允许拖拽。锁版保存最终 ordered_photo_ids，相框完整遵从。不能在播放端因日期又重排，把统筹者的手动位置撤销。

新候选有手动顺序时，新进入素材建议按默认时间位置插入，但保持既有项的相对人工顺序；标为需检查。是否恢复默认顺序提供明确动作、预览影响、保存修订，不静默重置。

## 7. 自动拼图算法

### 7.1 合并条件

以下四条件同时满足才形成自动组：

1. 照片已获当前用途允许并可用。
2. 在最终确认的照片顺序中**连续**。
3. `author_user_id` 相同，是同一位投稿者。
4. 时间属于本版允许的同一桶。

“照片里有四个人”“四个人各上传一张”“都选学生”“来自同一单位”不满足同作者条件。同名署名不一定同一账号；一个账号代不同人提交如何署名必须由来源规则确认，不能用显示名字去猜作者。

### 7.2 相同／接近时间分桶补充方案

| 精度 | 本版建议桶 | 可合并情况 | 不合并情况 |
| --- | --- | --- | --- |
| day | 已确认年月桶 | 同作者同年月不同日也可视为近时间 | 跨月即使只差一天不自动近邻合并 |
| month | 已确认年月桶 | 与同年月的 month／day 精度照片可同组 | 月份不同，或与只有年份照片混合 |
| year | 已确认年份＋year 精度桶 | 同作者都只知道同一年 | 不能把该年所有精确月日图都拉成一组 |
| unknown | 无自动桶 | 默认各自单图 | 不把全部未知图合成一组 |

这是保守落地方案而非“接近时间”已经定下的全部定义。默认不额外启用跨月 N 天阈值；将来启用须明确最大跨度、日期精度和连锁扩张规则，并重新生成候选与确认。

不能连续以每相邻两张“小于 7 天”把半年照片链式扩张成一组。启用阈值时需以组首与组末最大跨度约束，而不是只约束相邻差。

### 7.3 分组顺序

```text
取得当前用途的可用照片最终顺序
→ 计算每张确认时间桶
→ 从左到右扫描
→ 作者相同且桶相同且连续：延续当前段
→ 作者或桶变了，或时间未知：结束当前段
→ 每段按最多 4 张依序拆分
→ 输出单图／双拼／三图／四图组
→ 保存组成员 ID、顺序、布局和配置版本
```

拼图不改变全局照片顺序，不跨越中间另一位作者把同作者图抓回来。最终组由编排服务生成并写入候选／冻结包；各端渲染同组，不分别运行不同阈值算法。

### 7.4 数量与布局

| 连续张数 | 输出 | 布局建议 |
| --- | --- | --- |
| 1 | 1 张单图 | 全幅可适配或留边 |
| 2 | 1 组双图 | 双竖图左右，双横图上下，混合图适应容器 |
| 3 | 1 组三图 | 1 张较大＋2 张较小，主图仅布局位置，不赋人物权重 |
| 4 | 1 组四图 | 2×2 四宫格 |
| 5 | 4＋1 | 四图组后单图 |
| 6 | 4＋2 | 四图组后双图 |
| 7 | 4＋3 | 四图组后三图 |
| 8 | 4＋4 | 两组四图 |
| 10 | 4＋4＋2 | 两组四图后双图 |

具体尺寸按屏幕适配；不能为做满四宫格复制图片或生成空白假照片。没有“设为重点”字段，三图大图位置来自组内既定顺序和比例适配，不是系统评判贡献者重要。

### 7.5 图片、文字和点击

拼图页显示组作者及组可真实概括的日期，如年月，不给不同日图统一假精确日。每张单独描述不互相覆盖；短描述可在对应角标／字幕区显示，较长描述点击单图查看。

点组内任一图→单图查看器：完整图、其日期精度、原作者署名、获准描述→上一张／下一张→返回当前拼图页。返回保留当前组与播放暂停状态，不跳回第一张。

裁切必须尽量保留主体，支持看原图。人脸检测如作为本机视觉裁切辅助，不用于认人、关系排序或新增事实；失败用居中适配，合影避免裁掉人物。

## 9. 标签、关系、故事与集体信

### 9.1 标签与参与感

标签按合法可用素材聚合，适度字号变化可依据真实去重人数，不依据职位权重。显示真实参与数；一个人改标签 5 次不能算 5 个人。

关系可用简洁分组或柔和分布表现多人参与，不公开完整通讯录。某关系只有 1 人时不为凑画面虚构更多头像。

### 9.2 故事

故事页有标题、作者署名、正文、可用时间，长文分页或滚动；不能用三秒动画带过长故事。章节入口提供故事列表，可回到曾读位置。

故事手动确认顺序与工作台一致，无按领导／学生优先。多篇相同事件不同视角可以连续展示，但首版不自动揉成未经各作者确认的新事件事实；AI 集体信可合法概括，来源仍保留。

### 9.3 集体信

消费 letter_revision 对应已确认正文，不在设备临时重新生成。信标题、正文、署名可读，大字号分页；下一页不是直接跳过整封信，支持返回与字号调整。

若支持朗读，明确“朗读这封信”，使用系统声音并提示，不伪装某位老师或参与者原声。朗读与祝福音频互斥，用户可随时停。是否首发朗读依既有相框能力评估，非新增必需项。

组织信与参与者寄语署名规则不同，模板清单保存授权身份。相框不得将普通参与者信改成“某单位全体同仁敬上”。

## 10. 祝福气泡与原声

### 10.1 多人祝福展示

采用逐步出现的气泡或卡片，显示作者与短文字；多人可以同时在画面中有参与感，但不堆到读不清。建议可见 4—6 条，分批稳定循环，参数需设备阅读测试。

较长祝福点击展开完整内容。排序按冻结清单，用户修订去重，保证合法纳入的人都能在循环内露出；不因为新用户每秒提交就永久挤掉旧参与者。

有声音的祝福显示清楚的播放图标、时长和作者署名。只有声音时显示原声祝福卡而非空白文本气泡。

### 10.2 播放状态

未播放→播放中→暂停／结束。点另一段暂停前段；切章、进入绑定、返回日常或设备待机停止当前原声。录音时长与实际媒体一致，不用转写朗读代替原声。

默认原声由用户主动点播放；仪式主持人明确开启声音自动播放后，可按清单依次播放，不并行。背景音乐若提供，应播放原声时降低或暂停，不盖住说话。自动模式用户暂停后不得自行重启。

音频字幕仅在有可靠允许转写时提供，听不清处标注而非补编。文字祝福与音频转写可能不同，界面分别标明，不把二者强行等同。

下载失败、文件损坏显示单项无法播放，可联网重试；其他祝福照常可读。音频失败不重复发送一个新的投稿或通知。

## 11. 仪式大屏、现场补充与离线包

### 11.1 仪式播放

主持或统筹使用授权播放会话选择具体已锁版，展示版本号与就绪状态。大屏用仪式许可包，不通过一个永久公开 URL 暴露全部私人资料。

启动前预检图片、信、声音和完整下载；试播不产生正式受礼者拆封事件。正式开场与技术测试须有业务区分，不能测试一天就通知所有参与者礼物已打开。

### 11.2 现场内容

主码或可选现场子码均进入同人物同项目的补充队列。已有参与者不再完整填写四步；新来宾简短确认身份关系后上传照片、文字／声音祝福或故事。

现场成功投稿不自动上屏、不修改冻结包、不打断主持播放。通过安全、用途和必要检查后，进入礼后空间或显式生成后续补充版。若将来提供现场审核上屏，必须独立会话、主持确认与用途许可，不作为当前冻结版机制。

### 11.3 内容包结构与完整性

包至少包含：版本标识、模板版本、用途、人物允许资料、章节清单、照片原引用与可播放变体、拼图组、描述日期、故事正文、信、祝福文字音频、资源 hash、撤销校验版本、下载清单。

包内引用仅指许可用途内媒体；私人和仪式包分开。必要媒体签名和加密策略由安全方案实现，不把临时下载 URL 作为唯一长期离线资源。

下载新包写入临时区→校验清单和每项资源→标记可用→原子切换默认版本。中断或损坏保留旧可用包，不覆盖一半导致相框黑屏。不能回退到已撤销版本。

### 11.4 离线行为

| 情况 | 处理 |
| --- | --- |
| 已验证包存在、无网 | 正常播放该版，显示必要同步状态 |
| 包下载一半、无旧包 | 真实未就绪，不能正式开场 |
| 有旧包、新包下载失败 | 保留旧包，是否仍可使用由撤销与版本策略判断 |
| 离线首次打开 | 本地持久化真实事件，联机幂等同步 |
| 现场投稿网络失败 | 手机保留未提交状态，不计收到、不上屏 |
| 内容被撤回而设备离线 | 无法承诺实时抹除；联机先执行撤销与必要停包 |
| 播放中新版到达 | 下载校验但不突然换章；下次主动打开明确使用版本 |

## 12. 礼后相框与收到新心意

### 12.1 日常主页

拆封完成后进入既有相框日常能力，荣休成品保留可重看的专题。日常主页显示真实新心意入口、照片与记忆，不继续把长者锁在仪式流程中。

首条礼后记忆可提供“讲讲荣休后的第一天”轻引导，用户可跳过或以后再来，不强制完成多个设置才能看礼物。

### 12.2 接收链路

```text
共创者送时光真实提交
→ 每位人物独立接收资格校验
→ 媒体与内容处理通过
→ 进入人物受控空间
→ 已绑定相框同步
→ 提示有新的心意
→ 用户查看／回应
```

“已送出、已同步设备、已查看、已回应”分别记录。设备离线时送时光仍可进入人物空间，不能因此宣称相框已经看见。

收到新内容显示发送者署名、送出时间、照片和短文字，点击进入单份查看，多图可切换。发送给多人的内容在本端只是自己收到的一份，不出现其他收件名单。

### 12.3 查看、回应与再沉淀

P0 需可查看并进入既有回应能力；本版建议简短文字／语音回应，是否增补特定快捷回复按现有端能力确定。不新增 Instagram 通用聊天会话和在线状态。

回应只发给原发送者或明确获准对象，不广播给所有参与者。录音回应同样有权限、媒体处理、失败和重试状态。查看不自动发送“谢谢”，不替长者回应。

仪式照片、个人故事、信与礼后新内容保留原始时间与收件时间区别：旧照片按记忆日期，近况按实际送出／接收日期。后续专题或长河可引用合法素材，但不把礼后近况插入旧冻结仪式包。

### 12.4 接收管理

受礼者可关闭新参与者接收、限制特定用户、暂停通知、调整日子可提醒范围。旧统筹者已卸任也能由受礼者有效管理，不需要其回到项目审批。

关闭通知不等于删除内容，关闭接收不等于所有过去投稿被删除。限制作用在用户／人物接收关系，不靠换二维码假装屏蔽。

## 13. 数据记录与隐私

### 13.1 必需事件

| 事件 | 用途 |
| --- | --- |
| device_bound / unbound | 真实绑定与撤销 |
| pack_downloaded / verified / failed | 内容就绪与可靠性 |
| gift_opened | 项目首次正式打开与正式通知 |
| ceremony_started / completed | 正式仪式观看阶段 |
| chapter_opened / item_opened | 真实浏览，不等于发送或授权 |
| audio_started / completed / failed | 原声是否可用 |
| new_moment_synced / viewed | 新心意设备同步与真实查看 |
| reply_submitted | 回应实际成立 |

事件含设备、项目、内容版本、对象 ID、业务时间和幂等 ID，不写手机号与完整原文。测试播放、技术预检不计正式拆封。

### 13.2 隐私与缓存

普通设备设置不展示共创者电话、完整生日与账户标识。媒体缓存绑定授权人物与账号，加锁或待机依设备隐私设计；解绑与重置清理私有数据。

私人礼物下载地址不可作为永久对外分享地址，设备授权失效停止新下载。截图、离线副本与真实历史观看无法承诺全部追回，正式授权说明须清楚。
