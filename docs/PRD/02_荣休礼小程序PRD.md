# 荣休礼小程序 PRD

版本：1.0。依赖：[产品总 PRD](01_荣休礼产品总PRD.md)。本文定义真实用户页面、输入、结果与异常，统筹工作台详情见 [统筹管理 PRD](03_荣休礼统筹管理PRD.md)。

## 1. 信息架构

底部三个入口：**我参与的人、送时光、我的**。右上角消息铃铛是醒目的独立入口，显示未读标记；至少在三个一级页和统筹首页保持一致位置。表单沉浸页可以保留返回与保存状态，不因铃铛遮挡录音、上传或主按钮。

| 页面组 | 页面 | 业务目标 |
| --- | --- | --- |
| 共创入口 | 欢迎、身份关系、四步采集、预览、回执 | 形成一次真实共创 |
| 参与人物 | 已完成／未完成列表、人物详情 | 找到自己的参与与后续联系 |
| 送时光 | 照片文字编辑、收件人选择、发送结果 | 给一位或多位人物送近况 |
| 消息 | 列表、通知承接、成品查看 | 处理具体内容和重要日子 |
| 我的 | 资料概览、发起入口、本人统筹礼物与统计 | 直接看到自己负责的礼物 |
| 设置 | 个人资料、人物关系、本人共创记录、日子提醒、账号与接收设置 | 收起低频管理动作 |
| 统筹 | 发起五步、邀请、项目工作台及任务页 | 完成真实成品生产 |

页面路径必须保存项目／人物／通知上下文。回到上一页时恢复滚动、选择和已保存输入，不把角色或案例切换作为正式产品动作。

## 2. 登录、账号与入口恢复

### 2.1 登录时点

邀请允许先读取获准展示的最少资料。身份绑定、保存到账号、投稿、领取礼物、发送、管理关系和提醒必须有真实登录身份。获取微信会话不等于自动获授权读取电话，也不等于关注服务号。

登录后校验当前入口有效性和本人资格，再恢复目的页；登录取消保留允许保留的本机编辑，不报告操作成功。退出或换号清理前账号私有缓存，服务端草稿仍只归原账号。

### 2.2 编辑保存

- 编辑内容可自动保存，但产品不增加“草稿”一级列表或礼物状态栏目。
- 区分“保存中、已保存、未同步”，仅服务器确认后显示已同步。
- 上传文件成功、保存文字成功、整份投稿成功是不同回执。
- 两端同时修改同一修订，返回冲突与最新修订；不能把较老本机内容静默覆盖较新内容。
- 再次进入未完成共创时，先见欢迎页，再通过主按钮恢复到上次有效步骤。

## 3. 共创欢迎页 C00

### 3.1 展示内容

主标题说明“一起为受礼者准备荣休礼”，正文用短句说明照片、回忆和祝福将共同形成礼物。视觉主次：受礼者封面与称谓→主按钮→简洁人物介绍→组织署名与截止信息。

| 内容 | 数据来源 | 展示规则 |
| --- | --- | --- |
| 姓名与邀请称呼 | 项目确认资料 | 称呼为空时回退姓名，不写固定老师称谓 |
| 封面 | 项目封面 | 缺图使用品牌占位，不生成虚假人物照片 |
| 人物介绍 | 发起资料 | 有内容就展示简洁段落，可展开；不追加展示开关 |
| 主办名称与 Logo | 已提供组织信息 | 无主办不留空卡；不出现“主办情景示例” |
| 共创截止 | 实际服务端时间 | 显示实际日期与状态；不硬编码剩余天数 |
| 表达耗时说明 | 产品指导文案 | 可写约 10 分钟且可回来继续，不保证每个人完成时长 |
| 本人进度 | Participation | 已保存但未提交可说明有内容待继续，不增加草稿类别 |

主按钮“开始留下心意”或“继续留下心意”；未提交者每次从人物列表进入仍回此页。点按钮：首次→身份关系；已完成身份→上次有效采集步骤。次按钮稍后退出不改变提交状态。

截止后欢迎信息不继续催促已关闭的四步任务，主动作变为允许的补充或礼后入口。被撤销入口仅展示不可用和本人可访问的记录，不展示未授权资料。

## 4. 身份关系页 C01

### 4.1 字段

| 字段 | 规则 | 错误处理 |
| --- | --- | --- |
| 我的署名 | 必填，本版建议 2—30 个可见字符；可为希望展示的署名 | 空白、超限在字段旁提示，不自动改成微信昵称 |
| 主要关系 | 必选 1 项；方向“我是对方的什么人” | 未选择不能继续建立完整身份 |
| 其他关系 | 可选多选，不重复主要关系；数量建议最多 3 项 | 选到主要关系时去重或提示，不生成重复代码 |
| 联系手机号 | 不公开；复用本人已校验电话或主动提供 | 校验节点和是否提交阻断依总 PRD D-02，不以昵称冒充号码 |

不收关系起止年份、当前／曾经、长备注和特殊称呼。手机号与署名不同步公开，修改署名不改变用户身份键。

### 4.2 关系字典

首屏优先显示荣休礼高频关系；“更多关系”展开其余选项。主要和补充关系采用同一稳定代码，不用自然语言句子作为存储键。

| 稳定代码 | 选择标签 | 含义与约束 |
| --- | --- | --- |
| colleague | 同事 | 与对方共事的同级或一般同事，不强迫选择上下级 |
| subordinate | 下属 | 我是／曾是对方的下属，对方指导我 |
| leader | 领导 | 我是／曾是对方的领导，我指导对方 |
| student | 学生 | 我受过对方教学指导 |
| teacher | 老师 | 我教过／指导过对方，方向与 student 相反 |
| mentor | 导师 | 我是对方的导师，不是对方是我的导师 |
| mentee | 被指导者 | 我接受过对方长期指导，可适用于非学校关系 |
| friend | 朋友 | 平等朋友关系 |
| family | 家人 | 亲属关系总类，不再追问长关系备注 |
| spouse | 配偶 | 我是对方配偶 |
| child | 子女 | 我是对方的子女 |
| parent | 父母 | 我是对方的父母 |
| sibling | 兄弟姐妹 | 与对方为同辈手足 |
| grandchild | 孙辈 | 我是对方的孙辈 |
| classmate | 同学 | 与对方曾共同学习，不等于我是其学生 |
| schoolmate | 校友 | 与对方有同校经历 |
| collaborator | 合作伙伴 | 与对方合作，不默认组织上下级 |
| team_member | 团队伙伴 | 同团队、不适合领导／下属分类的合作关系 |
| neighbor | 邻居 | 生活邻里关系 |
| other | 其他 | 通用题库兜底，不能推断上下级 |
| unsure | 暂不确定 | 允许表达身份尚不确定，不伪造精确关系 |

同事、学生、领导、下属、朋友、家人及其他为高频基础项；进一步关系扩展是本版补充字典方案，需要产品与内容运营验收。已有旧代码兼容，不因改标签将关系反转。

### 4.3 关系对题库与权限的影响

主要关系决定话题推荐第一优先，补充关系可提供其他话题；只选一项就是主要关系。通用话题始终可用，不能用关系强制所有学生只讲考试、所有下属只讲工作。

学生专属话题需要主要或补充关系包含 student 才推荐；老师、导师、校友不能直接当成“我是对方学生”。其他／暂不确定进入通用题库，不能推定上下级。题库按关系、场景、启停和版本配置；题目下线不删除已经用该题写成的故事。

关系选择不增加管理权限、不自动建立双向互认关系、不自动开启教师节提醒、不公开联系方式。主要关系修改后推荐题更新，但本人已写故事保留，不能清空投稿。

## 5. 共创四步公共交互

顶部用简洁四步状态：印象标签、时光碎片、话题故事、祝福。显示当前步骤与项目称呼；允许返回已编辑步骤，跳过不会删除已存在内容，清空需要独立明确动作。

“下一步”保存当前有效输入并继续；“暂时没有，跳过”只将该步标记为暂缺，保留可以恢复的旧输入需告知，不能误删。保存失败时保留输入，提示重试与是否继续本地编辑。

所有表达区域邻近 AI 小叙。小叙不覆盖键盘、输入字数、图片操作、录音状态或主 CTA。具体协议见第 16 节。

### 5.1 礼前共创看板：看见参与，不制造社交噪音

共创者提交后可进入共创看板。看板用于降低独自填写的冷启动焦虑、提示内容方向缺口，并形成“一群人正在共同准备”的仪式感。首期不提供点赞、评论、排行、@、私聊或围绕投稿接龙。

看板至少展示：有效提交人数、关系类别汇总、内容方向及数量、仍为空白的方向、面向当前用户的一条补充建议。统计只能来自有效项目数据；人数按去重账号计算，处理中或已撤回内容不冒充有效产出。关系与方向的小样本需要做隐私阈值控制，不能借汇总反推出具体参与者。

| 展示策略 | 共创者可见内容 | 禁止内容 |
| --- | --- | --- |
| 惊喜准备 | 参与人数、关系类别、方向覆盖与空白 | 具体投稿、作者与片段摘要 |
| 一起准备 | 上述汇总，以及作者明确授权向本项目共创者展示的片段摘要 | 未授权原文、联系方式、精确私人关系、直接评论与回复 |

“允许进入礼物／仪式／礼后留存”不能自动等同于“允许礼前给其他共创者看”。授权片段需要独立、可撤回的 `peer_preview_allowed`；撤回后立即从看板移除，不影响其是否仍可进入礼物。摘要由原文安全截取或作者确认，不让 AI 改写成作者未表达的事实。

统筹者在项目设置或工作台选择展示策略，并能看到与共创者一致的预览。策略从一起准备改为惊喜准备时立即隐藏片段；切到一起准备时也只出现已取得独立授权的内容。

惊喜模式不得显示真实头像、姓名首字、精确提交时间或可反推个人身份的稀有关系。参与者区域使用匿名视觉占位，并明确说明“身份保持匿名”。一起准备模式的摘要查询必须显式过滤 `peer_preview_allowed = true`，不能以进入礼物、仪式展示或礼后留存授权代替。

### 5.2 礼中只读投屏

礼中投屏作为可选能力，首期只读展示匿名参与人数、关系覆盖和内容方向的变化，用于加强“大家一起准备”的仪式感。不做评论、弹幕、点赞、抢答、排名或共创者对话。统筹者可关闭投屏；样本过小或可能反推身份的分类合并为“其他视角”。

### 5.3 礼后由“被珍藏”走向“被回应”

礼后关系闭环以长者回应为核心，而不是继续增加共创者之间的互动。长者可以对整份礼物或具体内容留下文字、照片或声音；系统只向回应对象及被授权查看的人通知。没有真实回应时不制造“已回应”状态，统筹者代录必须标注代录身份。

## 6. 印象标签 C11

以短词选择为主；预设词根据主要关系推荐，也允许自定义。选择后显示选中状态与数量；选用时 1—5 个，全部不选可跳过。

同一标签按规范化文本去重，前后空白裁剪，避免“耐心”和带空格同词重复占位。自定义长度建议 2—12 字，违规或人身评价按实际安全策略处理，不能随意替用户换词。

不要求填写“为什么想到这个词”。AI 可建议可选择的词，不自动写入 5 个标签。标签汇总给相框时按允许展示的贡献与去重计数，不把一个用户多次改同一词计成多人支持。

## 7. 时光碎片 C12

### 7.1 页面与上传

推荐 1—2 张，最多 10 张。**一行一张完整卡片**，卡内图片、日期、短描述及操作有稳定顺序，不在窄屏并排两个编辑卡。

点选择照片→调用实际选图→生成上传卡。卡片先显示真实本机预览和进度，上传失败卡保留并可重试或删除，不凭占位图假报上传完成。超过可剩余张数时在选择或确认时阻止，并说明剩余数量。

统一卡片操作：查看大图、更换、删除。作者采集时的顺序表示本人素材编辑顺序，统筹展示顺序由全项目编排决定；本版不堆叠“前移、设重点”等按钮。

### 7.2 单卡字段

| 字段 | 规则 |
| --- | --- |
| 图片 | 必须是真实上传成功且最终处理可用的媒体引用 |
| 短描述 | 可选，每张最多 100 字，小叙邻近输入；不因选图隐藏已写描述 |
| 年 | 可选明确年份或不记得；范围随实际产品资料与合理校验配置 |
| 月 | 已知年时可选月或不记得 |
| 日 | 已知年月时可选日或不记得，日期按月份和闰年校验 |
| 时间来源 | 作者手填／确认 EXIF 建议；保留确认状态 |
| 口述成文 | 录音转写→预览→确认进入此卡描述，不作为声音祝福 |

日期三级选择器用紧凑的年／月／日三个控件，不把几十个年份平铺成文本。选择“不记得年”时月日清空并不可形成孤立具体日期；月变未知时日清空；月份变更导致原日无效时要求重新选，不静默改日期。

精度显示：只知年份显示年份，只知年月显示年月，全知显示日期；完全未知显示“时间待补充”或“不记得时间”，不能默认当前年份。EXIF 与手填冲突时以作者明确确认资料为准。

上传照片不会删除文字；更换图片保持描述并提醒核对是否仍匹配。删除卡说明同时移除本编辑中的日期和描述；已提交记录修改形成新修订。

### 7.3 口述成文状态

未开始→请求麦克风→录音中→停止→转写中→可编辑转写→确认。录音失败、权限拒绝、超时分别呈现原因，手写仍可用。确认转写后描述超 100 字时显示原转写并要求裁剪或润色，不能直接截断可能改变含义的内容。

未确认的转写不写入最终描述。取消返回原文，AI 润色只能以可读取、可拒绝的候选稿覆盖。转写音频保存期限按总 PRD D-10。

## 8. 话题故事 C13

### 8.1 话题卡布局

话题呈现为具有场景缩略图、短问题和动作的卡片。窄屏采用单张主卡或横向浏览，相邻卡露出边缘；不以三条细长问题按钮代替故事入口。图片仅是话题引导，不冒充受礼者上传过的照片，也不进入成品素材。

卡片状态：未写→开始聊；有编辑内容→继续写；已保存→查看故事。换一批仅更换推荐题，不删除已有故事；最多 3 篇，达到上限不再添加新篇，可编辑或删除旧篇。

### 8.2 故事编辑页

显示选定话题、正文区、小叙和口述成文。正文建议最多 2000 字，可以不配图，不额外要求配图来解锁下一步。故事标题可从问题继承并允许简短修改；不收繁琐关系年份或事实问卷。

若作者主动提供明确事件时间，保存精度并进入默认时间排序；没有时间时保留未知，AI 不根据“后来”“毕业”猜年份。该时间入口可放在可选补充，不强迫每篇填写。

保存关闭回卡片列表，卡片显示摘要和编辑状态。取消未保存编辑时说明影响；删除故事与从推荐列表换题是不同操作。

完整故事在相框作为独立可阅读内容，普通祝福用气泡／卡片，两种表达强度区分依素材种类，不以“领导最重要”打分。

## 9. 祝福 C14

页面同时提供方式一文字、方式二声音，允许一起提交。

### 9.1 文字

推荐区显示 2—3 条简短模板，“换一批”不改已采用正文。点击模板进入可编辑祝福，不替用户直接送出；“自己写一句”进入同一正文编辑区域，避免模板下再堆一个大输入框。

正文长度本版建议最多 200 字。小叙可以提供关系适配的起笔、润色；使用通用建议时不添加具体荣誉、职务、年份或并不存在的经历。

### 9.2 原声祝福

小叙头像旁直接呈现“你也可以这么说”的简短模板，如自我介绍、感谢一件事、期待下一程。模板可在录音时读取，不用“你不知道说什么”折叠入口增加一步。

核心操作：开始录音→停止→播放／暂停／删除。最长 60 秒，到上限自动停止并保留实际录音；录完能重新录，但覆盖旧音频前明确确认。上传和处理完成才是可提交状态。

录音时不自动清空祝福文字，也不在背景播放其他音频。应用切后台／来电中断时结束或暂停并提示实际保存结果；0 秒或空文件不能作为有效声音。

正式祝福不重复添加照片入口、不提供外部音频来源选择器，不将贴纸作为首版核心祝福类型。原生表情作为输入字符可按实际字体与安全策略支持，不代表另建表情包功能。

## 10. 预览与提交 C15／C16

### 10.1 本人预览

按标签、照片、故事、祝福汇总**本人内容**；每块可返回编辑，音频可试听，日期按真实精度展示。此处不是全体相框最终版，不暗示能看到他人原稿。

提交前显示简洁实际使用说明、必要确认和署名，不添加复杂用途矩阵。来源与授权随每项素材保存；只有私用许可内容不会因为项目要办仪式而自动取得仪式许可。

### 10.2 提交动作

1. 校验登录、身份字段、资料长度、媒体状态、项目仍允许当前类型投稿以及确认记录。
2. 内容全部为空时定位到可添加的步骤；是否标签单独允许提交按 D-03。
3. 固定一次清单修订与幂等键，按钮显示提交中并阻止重复创建。
4. 服务端提交成立后回执；后续安全处理状态如实展示。
5. 人物列表对应参与变已完成，进入回执页。

上传仍未完成不得标已送出；可以先等待处理或明确保存待继续。提交遇截止，服务端返回真实阶段，允许用户确认转补充队列，不静默换用途。

### 10.3 回执

展示提交成立、将进入整理或实际处理状态、本人可修改范围。可查看本人内容、回我参与的人、设置这个人的日子提醒。提醒授权可稍后，投稿不强制关注服务号。

修改已提交内容创建修订；如果旧稿已入仪式冻结版，明确新修改不会直接改变原版。撤回依总 PRD 的用途与受控撤销规则处理。

## 11. 我参与的人 P00／P01

### 11.1 列表

顶部两个标签：**左侧已完成，右侧未完成**，默认已完成。取消“找一位参与过的人”搜索入口。实际状态由本人有效参与记录决定，不人为把某位受礼者固定到某组。

卡片显示：人物姓名／称谓、封面、主要关系、相关荣休礼日期、本人的参与状态和具体下一步。日期、截止、最近发送分行排列，不能拼成无分隔的长字符串。

同一人物有多个项目时按人物聚合；存在未完成参与时在未完成组有该人物的未完成项目入口，已完成组也可体现其已提交历史。不能因为有一项未完成就抹掉所有已完成经历。卡片点入后明确选择相关项目，重复跨组展示不是重复创建关系。

| 操作 | 结果 |
| --- | --- |
| 点击未完成项目卡 | 回欢迎页；开始后恢复有效采集进度 |
| 点击已完成人物 | 人物详情、自己的参与、可查看成品与再送时光 |
| 继续填写但项目已关闭 | 当前阶段补充入口或结束说明，不回失效正式采集 |
| 无已完成参与 | 空状态引导完成邀请或查看未完成，不添加虚假人物 |
| 无未完成参与 | 显示当前没有待继续参与，不出现“已完成所有礼物”误导 |

### 11.2 人物详情

展示允许的基本资料、本人关系、本人已参与项目、最近本人送出、有效重要日子和主动作送时光。未公开成品不展示，其他共创者联系方式不展示。

关系与提醒修改入口可通往设置中的对应人物详情。接收关闭时禁用发送并说明无法送达，不暴露关闭的私密原因；本人历史仍按允许范围可读。

## 12. 送时光 M01／M02／M03

### 12.1 编辑页：照片与文字合并

参考生活照片分享的交互：上方可增删与预览的图片区，下方短文字输入与小叙，再显示下一步。取消“先选图再单独写一句”的两个分离页面。

| 字段／动作 | 规则 |
| --- | --- |
| 照片 | 0—3 张，真实选择与上传；单图大预览、多图紧凑预览；可大图查看、删除、更换 |
| 文字 | 0—100 字，字数可见；图片为空仍可只发文字 |
| 小叙 | 邻近文字，提供起笔与润色预览，不遮挡图像 |
| 下一步 | 至少一张可用图或非空文字，否则不可发送；媒体处理中明确等待 |
| 返回 | 保留本次输入，不发送 |

图片和文字不绑定同一必填规则。选图、更换图不能删除正文；取消选图保留原选择。提醒进入可预带人物与事件，但此页仍可编辑，不自动发送。

### 12.2 收件人页

顶部概览已选照片与短文字，下面按有效人物关系列表多选。每项姓名、头像或封面、主要关系和可接收状态；同一人物只一项，不按多个礼物重复出现。

选择与取消即时更新人数；至少一位，具体最多人数待 D-09。不可接收人物禁用并给最少必要说明，其他人仍可选。全部无资格时显示返回和可查关系，不让按钮误报发送成功。

从人物／提醒进入可预选该人物，并允许添加其他人物；事件关联只归适用人物，不把陈述某人生日的系统上下文扩散成所有人的事件。发送前提供内容与收件数量确认，但不再强制第三个完整编辑页。

### 12.3 发送与结果

冻结本次内容和收件人清单，各人物独立 delivery_id。发送中禁止重复创建，但允许返回查看状态。结果页逐项区分成功接收、等待处理、失败、资格变更。

- 全部成功：显示真实已送出人数，可回人物列表。
- 部分成功：突出已成功与失败人数，仅重试失败项；已成功收件者不可重复发。
- 全部失败：保留编辑与选人，分类处理可重试／不可接收。
- 请求超时：查询原发送记录，不能用新请求再次群发。
- 收件策略在选择后变更：按最新规则失败该人物，不影响其他人物。

“已送出”指进入该人物受控接收空间，不等于相框已同步或受礼者已看。如需展示设备到达或阅读须有对应真实事件，不伪造“已读”。每位受礼者不看到其他收件者名单。

## 13. 消息 N00

### 13.1 入口与阅读

右上角铃铛显示未读红点或清晰数量，颜色、触达范围与头像不同，不能藏在设置里。点击打开消息列表；实际进入详情或满足阅读条件才写 read_at，进入列表不自动把所有通知标已读。

列表直接展示事件卡：日期、标题、简洁原因、明确动作。不增加“小程序消息／服务号示意”切换，不在卡前放提醒授权状态大块说明。

### 13.2 四类关键卡片

| 类型 | 内容 | 动作与边界 |
| --- | --- | --- |
| 日子提醒 | 实际事件日期、人物、提醒理由 | 送一份祝福→送时光编辑，预选人物与事件 |
| 共创收集结束 | 真实结束状态、正在整理／候选已就绪 | 查看准备进度；候选就绪且有分享资格才可预览 |
| 正式拆封 | 受礼者已经正式打开、参与的礼物名称 | 查看已锁定且允许分享的最终成品 |
| 长者回应 | 受礼者对某次礼物或后续心意留下的文字、声音或照片回应 | 查看回应；只通知原内容作者或获准查看的参与者 |

候选预览注明仍在整理的实际状态；最终查看固定所通知版本，当前版本有变则给出明确切换。只有私人授权的照片、故事与音频不出现在共创者预览中。

消息中开启提醒不是自动外发授权；未开业务提醒不凭空产生生日卡。实际收集结束和正式拆封属于项目通知，与用户是否开启生日提醒分开。

旧通知点击后重新检查关系、接收和分享资格。内容撤销、项目取消、通知令牌过期分别提供安全回退；不以旧链接恢复已失效权限。

“送达／已打开”只说明交付链路，不等同于关系价值完成。长者回应作为独立事件记录回应者、回应对象、内容、授权范围和时间；界面从“被珍藏”进一步呈现“被回应”。长者不必回应每位共创者，也不显示未发生的虚假已读或统一感谢。统筹者代录时明确标注代录身份，不能冒充长者本人。

## 14. 我的 U00

### 14.1 页面布局

上部头像、署名、简短个人表达；右侧齿轮进入设置。主体依次：明显的**相框／生成礼物图标与发起卡**→本人统筹统计→我的礼物列表。

“为重要的人准备礼物”卡用已有品牌相框图形，不只放一个小加号和文本链接。点击进入真实发起入口，不展示泛礼品商城未实现功能。

### 14.2 我的礼物与统计

仅有本人有效统筹权限的项目进入可操作列表，已完成且本人具有历史查看资格的项目进入历史组。作为普通共创者参加的礼物不混入此列表，不能显示别人的统筹项目却提供“继续整理”。

绿色统计区建议：正在统筹项目数、已经完成项目数、已提交参与人数／目标人数。首页跨项目参与统计使用“人次”，或明确去重后的“人数”，不把同一人参加两项目的两次贡献当成两位用户。

礼物卡：封面、受礼者、礼物名称、统筹中／已完成、当前任务、实际共创进度。统筹中可以细分收集中、待检查、待定稿、待交付；不把统筹列表统一叫“共创中”。

入口动作：继续统筹／查看成品／查看交付。不再单独点击“我的礼物”才能看到列表，不设“我发起的／我统筹的”重复分组，不提供草稿分组。

移交后项目从当前可管理列表移出，历史创建记录不抹除；若仍为共创者，可以从参与人物找到本人投稿。

## 15. 设置 S00

### 15.1 个人资料 S01

可编辑头像、显示姓名／署名及已收集的个人简介；手机号在独立验证流程中修改。头像真实上传，裁切预览后确认；保存失败保留编辑。

修改个人展示资料不追溯改写历史锁版署名。新投稿使用当前署名，已提交未锁素材可提示是否更新；该更新必须有明确动作与修订。

### 15.2 我与参与人物的关系 S02

列表展示所有已建立人物连接，不只当前项目人物。点每项进入同方向的主要关系单选、其他关系多选编辑；保存只改变本人此人物关系，不修改其他人的关系，也不默认重写历史成品标签。

删除／解除关系前说明：停止后续提醒与发送资格，不自动删除所有原始投稿。被受礼者限制的关系不能通过重新选择“朋友”恢复权限。

### 15.3 我的共创记录 S03

跨人物、跨项目的本人记录列表，按提交时间新到旧，可按人物／状态筛选。每项项目、人物、提交时间、类型概览与真实状态；点进管理本人照片、故事、祝福。

管理动作区分修改、撤回投稿、删除本人列表记录。批量操作本版可先不做，但必须能逐项管理；错误和权限变化定位具体记录。已锁版记录明确不直接改写原包。

### 15.4 重要日子与提醒 S04

按人物列出实际可见事件和开启状态，再进入单人物配置：开启哪些日子、提前／当天、应用内、外发渠道可达性、免打扰与暂停。个人偏好只控制本人，不改变其他参与者提醒。

日期由受礼者或授权资料管理员确认，普通参与者不能随意改老师生日给所有人推送。可提交纠错建议，待确认前不改调度。

### 15.5 受礼者接收设置

已绑定受礼者在账号适用入口管理既有参与者接收、是否允许新扫码者、特定人物／用户限制、日子可提醒范围、设备与账号。普通共创者的设置不显示这些管理员级能力。

## 16. AI 小叙统一规格

### 16.1 形态与触发

采用统一人物头像和短提示，依输入语境展示“需要帮忙优化吗”“你也可以这么说”。可贴在编辑卡边缘但不能遮挡内容，支持收起。输入为空：起笔模板与引导；有内容：润色、压缩、口述整理。

| 输入 | 可以帮忙 | 不能帮忙 |
| --- | --- | --- |
| 人物介绍 | 整理发起方提供的简介 | 自动编造履历、奖项、退休年份 |
| 照片描述 | 保留原意压缩为 100 字以内 | 凭画面猜人物姓名、确切时间 |
| 故事 | 提问、组织段落、口述整理 | 添加未讲过的冲突、对话和结局 |
| 祝福 | 起笔、语气调整、录音模板 | 冒充本人已经表达或自动送出 |
| 送时光 | 一句近况润色 | 增加未上传的生活事件 |
| 集体信 | 提供编辑建议 | 绕过统筹确认或冒充组织授权 |

### 16.2 应用候选稿

请求只发送当前场景必需内容及获授权上下文，不发送手机号等无关字段。保存请求对应 input_revision；候选生成期间原文有变化，则提示基于旧稿并要求重新选择，不能覆盖新稿。

候选可预览、应用、继续改、放弃。应用形成一次编辑修订，提供撤销恢复前文；进入锁版后的编辑仍不能改冻结信。超长候选明确提示与可用压缩，不直接截断。

加载、失败、限流、取消均有状态；关闭助手不删除文本。后台返回过期候选不自动弹出遮挡当前其他页面。

## 17. 小程序验收清单

现场补充复用完整共创流程，不另造一套简化投稿编辑器。现场欢迎页只调整场景说明，明确“约 10 分钟、有些内容可跳过、可以稍后继续”；已登录且已有关系的人直接恢复流程，新参与者先完成署名和关系后进入四步共创。

项目完成卡在最终成品尚未允许查看时仍可展示项目完成信息，但不得提前打开最终成品。完成卡包含项目名称、参与人数、受礼者封面、二维码、点击保存和一键分享；二维码保存的是卡片，分享发送的是受控项目链接。

| 编号 | 检查 | 预期 |
| --- | --- | --- |
| MP-01 | 三个一级入口与消息 | 人物／送时光／我的正确，铃铛醒目且未读准确 |
| MP-02 | 未提交从列表反复进入 | 都先欢迎，再继续原有效步骤 |
| MP-03 | 完成、未完成标签 | 左已完成默认，右未完成；真实数据分类 |

| MP-06 | 照片窄屏编辑 | 一行一块、日期控件不展开成密集年份文本 |
| MP-07 | 上传、换图、取消 | 原文字保留；失败图可重试；数量不超 10 |
| MP-08 | 不知年／月／日 | 三级依赖正确，无伪造日期；闰日校验一致 |
| MP-09 | 口述成文 | 预览确认才进描述；原声不自动当礼物音频 |
| MP-10 | 换话题／换祝福模板 | 既有输入不丢；故事最多 3 篇 |

| MP-13 | 整体空白提交 | 阻止；不回假成功，不改变人物完成状态 |
| MP-14 | 重复点提交与超时 | 同一清单幂等；回原真实结果 |
| MP-15 | 送时光编辑 | 图文合一，0 图有文／有图 0 文都可继续 |

| MP-24 | 卡片长文与无图 | 布局可读，主按钮、键盘和小叙不互相遮挡 |
预览以可横向滑动的拍立得卡片呈现。卡片需兼容照片／视频、音频条和纯文字三种载体，不得假设每个投稿都有图片。修改入口统一放在分组右上角；时光碎片和话题故事逐条提供“公开展示／仅 TA 查看”，默认仅 TA 查看。这里的公开仅指当前项目的“一起准备”看板，仍受独立授权控制。

同一段近况最多 6 张照片，不限制展示型字数计数；后端仍应有防滥用长度上限。编辑器使用拍立得式组合卡：已选照片在上、选择照片入口居中、文字框在下，文字框内提供语音转文字、AI 优化和撤销。
