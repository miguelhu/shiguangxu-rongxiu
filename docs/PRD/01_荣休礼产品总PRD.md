# 拾光叙荣休礼产品总 PRD

版本：1.0。范围：真实荣休礼产品。

## 1. 产品定义

荣休礼把组织、同事、学生、亲友共同提交的照片、回忆和祝福，整理为一份在荣休仪式上打开、之后留在相框中的礼物。仪式是第一次集中交付；礼后继续接收近况与问候，使一次赠礼变成持续关系。

产品不是通用聊天工具，也不把退休后的连接变成返聘、工作任务或组织考核。荣休礼首版围绕一位受礼者建立项目和长期人物空间，不扩展为贺寿礼、婚龄礼等其他礼品 PRD。

核心结果：

1. 发起方能建立身份明确、日期清楚、有交付目标的礼物。
2. 共创者能以较低表达压力留下真实内容，并保留自己的表达与使用权利。
3. 有统筹者时，能检查素材、确认 AI 祝福信并锁定仪式版本。
4. 没有持续管理者时，流程有预先配置的处理方式，不无限等待一个已经离开的人。
5. 受礼者能安全绑定、顺畅拆封，看到多人心意，并能听到原声祝福。
6. 礼后参与者能从重要日子提醒继续发送照片与文字，受礼者可以控制接收。

## 2. 范围与交付端

| 组成 | P0 能力 | 不在本版展开 |
| --- | --- | --- |
| 小程序 | 身份关系、四步共创、本人投稿管理、参与人物、消息、送时光、个人设置 | 通用私信、群聊、社交广场 |
| 统筹工作台 | 发起、邀请、进度、照片／故事／祝福检查、AI 信、成品预览、锁版、移交 | 组织绩效、复杂多管理员会签 |
| 相框与仪式播放 | 安全绑定、仪式内容包、照片拼图、故事、信、声音祝福、离线播放、礼后收礼 | 用赠礼资料训练受礼者数字分身 |
| 系统与运营支撑 | 权限、安全检查、内容处理、版本分发、通知调度、异常处理与审计 | 未经确认的全天候人工服务承诺 |
| 服务号渠道 | 具备实际账号能力时外部提醒与回流小程序 | 未授权用户的任意长期推送 |
| 采购与履约接口 | 订单／项目／设备关联，组织资料来源与交付状态 | 支付、退款、发票及物流的完整商业 PRD |

统筹功能必须有真实的小程序入口。“统筹管理”是业务职责划分，不要求另造一个独立 App；复杂批量组织资料可由管理网页承接，但与小程序使用相同项目、权限、版本。

荣休礼礼前默认不让受礼者参与其他人的筹备，也不开放最终成品。取消模式选择不等于取消服务端礼前访问限制。本人发起荣休礼作为兼容场景保留：其可以提交基本资料，但他人筹备内容和最终成品的提前可见策略见 D-08，不能简单因为创建者与受礼者相同就开放全部资料。

## 3. 角色及其权限

### 3.1 角色定义

“发起人”“统筹人”“主创”在礼物管理语境下合并为统筹职责，不在“我的礼物”分成两套重复列表。仍需要区分采购身份、项目创建记录和当前内容管理授权。

| 角色 | 能力 | 明确限制 |
| --- | --- | --- |
| 创建者 | 提供基本资料、建立项目、指定或接受统筹职责、选择处理策略 | 创建记录不会因移交消失；不是永久管理权 |
| 采购经办 | 订单、组织资料、履约进度 | 仅采购不获得投稿全文、审核、锁版权 |
| 当前统筹者 | 邀请、检查、编排、确认信、预览、锁版、处理项目例外 | 不能冒充作者授权，不能改写锁定历史版本 |
| 共创者 | 编辑和提交自己的内容、控制授权、管理自己的人际关系和提醒 | 不能查看他人未获准展示的原稿，不能确认仪式版本 |
| 受礼者 | 正式收礼、礼后查看与回应、设置接收范围和可提醒日子 | 礼前访问按策略控制；不能替别人扩大原始投稿授权 |
| 协助绑定者 | 在受礼者授权下协助设备与账号操作 | 不因帮忙输入验证码而获得永久内容管理权 |
| 系统 | 校验、整理、按明确策略生成和分发、记录提醒 | 不凭 AI 推断事实，不替用户作授权决策 |
| 平台处理人员 | 按工单处理违规、争议、交付故障 | 非默认全量内容可读；访问和操作留痕 |

一个账号可以拥有多个角色，每次操作按“当前用户＋项目＋角色有效期＋对象授权”判断。前端隐藏按钮不能代替权限校验。

### 3.2 可选统筹与任期

已确认：持续人工管理可选，不能要求每个项目礼后必须有人一直负责。

本版补充方案：创建者默认承担筹备统筹，也可指定另一人接受；无接受者时使用明确配置的系统整理策略。人工模式在收集、检查、信件和锁版阶段需要有效统筹者；自动模式不能被伪装成“某人已经检查”。

项目需记录 `coordination_mode`、`review_due_at`、`fallback_policy`、角色任期。礼后接收走独立规则，统筹任期结束不会自动关闭所有参与者的问候渠道。具体自动发布范围、默认模式和任期见 D-01，属于上线前必须定案的业务策略。

## 4. 核心对象

| 对象 | 业务含义 | 唯一与归属规则 |
| --- | --- | --- |
| User | 登录账号 | 微信标识、手机号关联必须经过校验，姓名不是账号键 |
| Person | 真实受礼者人物 | 同名不自动合并；多个礼物可归于同一个经确认人物 |
| Project | 一次荣休礼 | 归属一位人物，具有收集、成品、交付阶段 |
| Participation | 用户对某项目的共创参与 | 用户与项目唯一；保留提交状态和来源入口 |
| Connection | 用户与某人物的关系 | 用户与人物唯一；可以关联多个项目 |
| Contribution | 一次提交及其修订 | 作者、项目、用途、时间、来源可追溯 |
| Fragment | 照片、故事、标签、文字或声音 | 每项独立状态与授权，不把整个作者作为一项素材 |
| PresentationItem | 成品中使用的展示项 | 指向具体素材修订；裁切、顺序、展示稿不覆盖原稿 |
| Letter | 多人素材整理形成的信 | 输入清单、生成版本、编辑、确认人可追溯 |
| CeremonyVersion | 锁定的仪式快照 | 不可变清单、顺序、文字、媒体、授权证据与模板版本 |
| DeviceBinding | 设备、账号和人物关联 | 激活凭证、绑定确认、解绑记录，不按名字绑定 |
| Moment | 礼后送时光内容 | 一份编辑内容对应多条独立收件记录 |
| Occasion | 人物可提醒事件 | 日期、历法、地区、来源、可见资格和启停 |
| Reminder | 用户对人物事件的提醒实例 | 用户＋人物＋事件＋发生年度／日期去重 |
| Notification | 业务通知 | 阅读状态与外发渠道投递状态分开 |

同一用户在两个荣休礼中为同一人物投稿，关系和生日提醒只保留一套，但两个项目的投稿、成品和交付状态分别保留。

## 5. 生命周期与状态

### 5.1 项目阶段

| 状态 | 进入条件 | 可进行动作 | 离开条件 |
| --- | --- | --- | --- |
| configuring 配置中 | 创建记录成立，资料未完成 | 填资料、选择策略 | 必需资料完整并确认开启收集 |
| collecting 收集中 | 入口可用、时间有效 | 邀请、共创、统计、素材预检 | 截止或有效统筹者结束收集 |
| preparing 成品准备 | 已停止礼前正式收集 | 检查、编排、生成信、预览 | 门禁满足后锁版 |
| frozen 已定稿 | 仪式版本冻结成功 | 分发与下载；接受另归属的补充 | 内容包可用且正式交付 |
| delivered 已交付 | 设备／受控播放器具备可用版本 | 绑定、拆封、现场补充 | 受礼者第一次正式打开 |
| opened 已拆封 | 正式开场被授权触发 | 仪式播放、通知参与者 | 仪式结束后转礼后使用 |
| ongoing 礼后持续 | 仪式结束或确认转日常 | 送时光、回应、重要日子、回忆沉淀 | 接收关闭、项目归档或终止 |
| cancelled 已取消 | 有权人员确认取消 | 本人记录与允许保留的信息 | 不可继续原筹备流程 |

`needs_attention` 是异常标记：资料缺失、全部内容不可用、包分发失败等，不代替所有业务阶段。时间到了不会自动等于已经交付、拆封或结束。

### 5.2 内容状态须分维度

不能使用单一“已完成”表示素材全部状态。至少分为：

- 编辑：编辑中／已提交／修订中／已撤回。
- 技术与安全：处理中／通过／需调整／被限制。
- 成品选择：候选／纳入／本版移除。
- 人工检查：待检查／已检查／因变动需重检。
- 版本引用：未被锁版使用／被哪些版本使用。
- 投递：待接收／已入接收空间／已同步设备／已读。

已提交但处理中可计入“已提交人数”，不能计入“可用素材数量”。本版移除不等于作者撤回或安全拒绝。

### 5.3 三套“完成”口径

| 页面语境 | 未完成／进行中 | 已完成 |
| --- | --- | --- |
| 我参与的人 | 该项目尚无有效提交，存在邀请或编辑进度 | 该次共创有效提交成功 |
| 我的礼物 | 当前用户负责、尚未完成交付的统筹项目 | 已完成交付的受管理项目；保留拆封状态 |
| 成品检查 | 相应材料版本尚未确认 | 对当前材料清单完成检查；变动后可能失效 |

仪式截止后未投稿的人不能显示虚假的“已完成”。归档可单独处理，不能逼迫其继续一个已经关闭的四步表单。

## 6. 一个共创入口贯穿阶段

主共创码使用稳定入口标识解析项目、人物和当前阶段，不存手机号、私人内容或管理权限。

| 当前阶段 | 已识别参与者 | 首次参与者 |
| --- | --- | --- |
| 收集中且未提交 | 展示欢迎页；开始后恢复有效进度 | 欢迎页→身份关系→四步 |
| 收集中且已提交 | 本人提交回执、查看／修改本人内容 | 欢迎页→新参与流程 |
| 已截止／已冻结 | 简化补充入口，明确不进入原仪式版 | 依项目接收策略开放补充 |
| 现场 | 保留身份，直接选择照片／祝福等简化动作 | 一次身份关系确认后简化投稿 |
| 礼后 | 人物空间与再次送时光 | 依受礼者的新参与者接收策略处理 |
| 入口停用 | 登录后可保留本人记录入口 | 不暴露更多人物或历史内容 |

现场专用二维码可选，是主入口的子渠道，可设置时间窗与来源。没有专用现场码仍可用主码补充。子码到期不删除已经成立的投稿或关系。

邀请码、管理邀请、设备激活凭证用途不同。普通共创扫码不能触发管理员授权或读取未公开成品。

## 7. 共创数据与表达规则

### 7.1 身份关系

关系方向固定为“我是受礼者的什么人”。主要关系单选，其他关系可选多选。关系代码见小程序 PRD。取消关系起止年份、当前／曾经、长备注和特殊称呼补充，不因此颠倒上下级关系。

署名和联系电话分开：署名用于成品署名，电话用于账户与未来连接，不向其他共创者公开。电话收集与强校验节点见 D-02。

### 7.2 四步

| 步骤 | 内容 | 规则 |
| --- | --- | --- |
| 印象标签 | 预设／自定义短词 | 选用时 1—5 个，不追问每个词的原因，可跳过 |
| 时光碎片 | 每张照片＋短描述＋拍摄时间 | 推荐 1—2 张，最多 10 张；描述每张最多 100 字，可不写；日期可未知 |
| 话题故事 | 话题卡进入完整故事输入 | 最多 3 篇，可不配图，可跳过，字数上限见参数表 |
| 祝福 | 简短文字和／或原声 | 可同时提交文字和声音；录音最长 60 秒 |

步骤可以跳过，整体提交不能只有空白；本版建议只有标签也不足以独立形成可交付成品，但允许成为一次有效参与，详见 D-03。共创参与有效性和整个礼物的成品最低条件不能混为一谈。

录音口述成文：转写、由作者确认后写入文字字段。声音祝福：保留原声，作为实际礼物媒体。转写原声不默认纳入成品；未告知且未获得允许，不做长期保留。

### 7.3 AI 小叙

所有需要表达的输入邻近位置提供小叙入口，包括照片描述、故事、祝福、近况、人物介绍、邀请寄语、信件编辑。提供起笔模板、口述成文或润色建议；原文已有内容时先预览再应用，并能撤销。

不得自动填写、自动提交、自动改名字日期、把猜测写成事实。事实字段及联系电话不需要“润色”。AI 失败不阻断手写和投稿，AI 处理期间其他素材可保存。

## 8. 时间排序和自动拼图的公共规则

以下是跨小程序、工作台和相框必须统一的规则，算法与验收详见相框 PRD 第 6—8 节。

**BR-PH-01**：照片默认按用户确认的拍摄／事件时间从早到晚。EXIF 仅可建议，作者确认后采用；上传时间不能冒充拍摄时间。

**BR-PH-02**：支持年、年月、年月日、完全未知。显示精度不超过输入精度；未知时间默认排在已知时间之后。

**BR-PH-03**：统筹者可上下拖拽调整照片和故事的展示顺序，不出现“设为重点”，不用关系身份权重排序。相框使用已确认的展示顺序，而不是收到包后自行重排。

**BR-PH-04**：先得到最终照片顺序，再检测其中连续的同一投稿作者、同一时间段照片，自动形成拼图。

**BR-PH-05**：一组最多 4 张，1 张单图、2 张双拼、3 张三图、4 张四宫格；多于 4 张连续照片拆组，不丢图。

**BR-PH-06**：不同投稿者不会因为同年、同关系、同单位或图中人数相同而自动合并。“一位作者提交 4 张”与“四位作者各 1 张”不是同一种条件。

**BR-PH-07**：图片合并展示不合并原始资料。每张保留原图、描述、日期、作者、授权及可追踪来源。点击可单独查看。

**BR-PH-08**：同时间段和接近时间阈值尚未全部定案，本版采用可配置的保守分桶方案，见 D-04；不擅自把任何年份相近的照片揉成一组。

故事默认按已知事件时间排序，未知时间靠后；没有时间输入的故事不由 AI 推测年份。工作台可拖拽改变故事展示顺序。

## 9. 成品构成、检查和锁版

成品推荐七章：开场、大家眼中的你、一起走过的照片、几个重要故事、大家写给你的一封信、大家的祝福、下一程。不是职业履历时间线界面，也不能为凑齐章节编造素材。

有人工统筹时：

1. 分别检查照片、故事、祝福。
2. 处理事实冲突、授权不符和不可用媒体；保留原稿。
3. 从允许纳入的标签、描述、故事、祝福、确认人物资料生成集体信。
4. 统筹者可重新生成、编辑并确认这封信。
5. 按真实相框顺序预览完整成品。
6. 明确确认仪式版本，生成不可变快照并分发。

检查页只呈现当前类别，不再嵌套“看照片／看故事／看祝福”重复导航。照片、故事的顺序调整触发编排变动；修改源文、授权、纳入清单会影响对应检查、信和预览有效性，详细失效矩阵见统筹 PRD。

AI 信是多人素材的整合，不是某位作者投稿的冒充信，也不是默认组织公文。涉及组织联名、官方荣誉或所有人署名需要相应确认和授权。

锁版不关闭全部未来投稿。迟到、现场和礼后内容进入独立队列，不覆盖已经确认的仪式包。发布新版本须重新确认，记录原因并显式选择，不静默替换正在播放的版本。

## 10. 授权、可见性与撤回

### 10.1 使用范围

| 范围 | 允许对象 | 规则 |
| --- | --- | --- |
| 本人编辑 | 作者 | 草稿与未提交内容不向普通参与者开放 |
| 筹备检查 | 当前有效统筹者及获授权处理人员 | 必须告知处理目的，不默认所有采购经办可读 |
| 私人收礼 | 受礼者及其明确授权的使用者 | 不等于对所有共创者公开 |
| 仪式展示 | 获准仪式播放器／现场受众 | 需要仪式用途允许，私密祝福不能直接上大屏 |
| 参与者成品预览 | 符合项目资格的共创者 | 使用单独允许分享的清单，可有不同于私人版的内容 |
| 长期保存与回应 | 人物空间允许对象 | 尊重源作者允许范围和受礼者接收设置 |
| 外部公开传播 | 另行获准对象 | 普通投稿同意不能推导为营销、公开平台或媒体使用 |

不需要在共创预览页增加复杂“用途选择矩阵”，但须在提交前有简洁、可读取的实际使用说明及相应确认。私人、仪式、参与者分享、公开传播不能合并成无限授权。具体默认授权组合见 D-05。

### 10.2 删除、移除、撤回

- 删除编辑中照片：从本人未提交内容移除。
- 统筹者移除：仅从本次成品候选中排除，作者原投稿和本人记录仍在。
- 作者撤回：撤销后续使用资格，阻止新版本使用和新投递，触发已有受控展示的处理任务。
- 删除本人记录展示：不等于撤回素材，操作必须明确其影响，不能用同一个含糊“删除”覆盖两种行为。
- 作者修改已锁版素材：形成新修订；旧仪式快照不会被直接改写。若为安全、隐私或撤回，则使用撤销清单、停止播放或新版本替换机制。

离线设备已经持有的数据不能承诺即时远程抹除。联机后先同步撤销状态；严重风险可停用整包，再给出可用替代包。留存期限、撤回响应和安全紧急处理必须在上线前定案，见 D-10。

## 11. 通知与礼后连接

### 11.1 业务通知

| 类型 | 真正触发条件 | 点击后 |
| --- | --- | --- |
| 收集结束 | 服务端收集状态转 preparing 且参与资格符合 | 查看有权分享的成品准备进度／可用候选预览 |
| 正式拆封 | 最终版存在，开启事件真实发生，统筹设置允许推送 | 查看被授权的最终成品 |
| 重要日子 | 日期已确认、事件对本人可见、本人开启提醒、接收有效 | 携人物与事件上下文进入送时光 |
| 需要调整 | 本人内容失败、争议或被限制 | 本人素材及明确修改原因 |
| 新心意／回应 | 真正产生可查看的新内容 | 对应内容或回应，不发无内容召回 |

收集结束不保证 AI 信或整包已准备完毕；不能展示空白相框却标成最终版。正式拆封通知在锁版时不提前发送，设备绑定不等于拆封。

### 11.2 重要日子

P0：生日、适用地区的教师节；荣休周年作为可选事件。生日来源于受礼者或获授权资料，不从名字、职务、年龄推测。教师节不能仅由“学生关系”认定受礼者必然为教师，需要人物事件资格。

每个人物事件只生成一条本人提醒卡；阅读不等于已发送。成功提交给此人物的关联心意后标记已行动，取消尚未外发的同事件提醒。草稿、上传中、发送失败不能标记已行动。

业务提醒开关、应用内卡片和微信外发资格分别保存。服务号作为真实外部渠道需实际账号能力验证；无渠道权限时保留应用内消息，不假报外发成功。已关闭提醒、被移除、人物关闭接收，在发送前再次检查并停止任务。

日期支持来源与精度：公历、农历、出生年份可选、地区与时区。农历算法、闰月和 2 月 29 日替代日见 D-06，没有可靠策略时不能按错误日期推送。默认提醒时间、频控见参数表，都是产品建议，不是平台限额。

### 11.3 送时光

两页闭环：第一页合并照片和文字，第二页选择多位收件人。最多 3 张近况照片，文字最多 100 字；照片或文字可以独立发送，全部为空禁止发送。

选人来自有效人物连接，不来自“我统筹的项目”名单。必须按人物去重，多项目同一人物不重复收件。每个人物独立做资格、接收和投递判断，产生独立结果；某人失败不能阻止其他人收到，也不能把其他人重复发送。

编辑内容创建一次，各收件者获得独立受控内容实例或引用。每位收件者只能看到自己收到的版本，不看到其他收件者名单或私有关系。收件前、投递前、设备同步前重新校验权限。

## 12. 设备与正式拆封

未绑定入口只显示拾光叙品牌和通用产品说明，以及实际绑定入口。二维码扫码与手机号验证两种方式并列；不展示受礼者姓名、照片、单位、成品或私人列表。

手机号验证码仅证明手机控制权，不能单独证明这个账号有权领取某份礼物。还需要设备／订单领取资格、有效激活凭证或经授权的邀请。凭证与项目设备关联由服务端处理，用户不能仅输入任意姓名绑定。

设备激活、账号绑定、成品包就绪、第一次正式打开是四个不同事件。设备已经激活但包未完成时呈现真实准备状态；不要提前标记拆封。正式播放同一冻结包，不在播放中接入现场新投稿。

本版补充事件定义：`gift_opened` 以有效用户主动打开、锁定版正式开场成功呈现为准；`ceremony_completed` 记录仪式到达结束或用户确认结束。正式拆封通知使用前者，重复播放和第二台设备不重复触发同项目通知，见 D-07。

### 13.2 必须具备的服务能力

- 解析入口并返回当前阶段、本人参与状态和允许动作。
- 保存编辑修订，提交时固定作者与完整素材清单；重复点击按幂等键回同一结果。
- 处理媒体并逐项返回失败，不能把上传按钮成功当作最终入库。
- 按项目角色获取进度与素材；普通共创者读取本人范围。
- 按 revision 提交排序、检查确认、信件确认、锁版和移交，冲突时拒绝覆盖并返回最新版本。
- 生成和分发不可变内容包，提供下载校验、可用版本及撤销清单。
- 为多收件送时光创建独立投递，并允许仅重试失败项。
- 为三类通知建立真实业务事件、授权视图及渠道投递任务。
- 验证领取资格、绑定设备、幂等记录首次拆封与仪式结束。
- 响应关系接收限制、提醒关闭与内容撤回，取消未执行任务。

此处是业务契约，不限定接口风格、数据库或具体 AI 供应商。

### 13.3 业务错误与恢复

各端展示相同业务结果；错误码是接口语义建议，不要求将英文码直接显示给用户。

| 错误语义 | 发生场景 | 恢复原则 |
| --- | --- | --- |
| LOGIN_REQUIRED | 会话失效 | 登录后恢复目的动作，不自动重新提交 |
| PERMISSION_DENIED | 角色移交、关系失效或对象无权 | 刷新允许动作，保留本人可读取的内容，不泄露他人资料 |
| ENTRY_EXPIRED | 共创子码、设备会话过期 | 依凭证类型刷新／换有效入口，不能恢复原管理权 |
| STAGE_CHANGED | 截止、锁版或取消发生 | 告知当前归属，转补充须得到明确确认 |
| REVISION_CONFLICT | 编辑、排序、确认、移交并发 | 读取最新版本并对比，不静默覆盖 |
| MEDIA_NOT_READY | 上传／转码仍在进行 | 保留输入，等待或重试原媒体，不报已发送 |
| CONTENT_RESTRICTED | 安全、用途或撤回不允许 | 定位具体项，不能重试绕过限制 |
| RECIPIENT_UNAVAILABLE | 选人后对方关闭接收 | 失败该人物，其他收件者继续 |
| RESULT_UNKNOWN | 请求超时且不知是否执行 | 查询原幂等记录，不以新键重复创建 |
| PACK_UNAVAILABLE | 资源缺失或包校验失败 | 修复／重下载允许版本，不破坏旧可用包 |

### 13.4 空内容和边界降级

1. 项目已有邀请但没有任何提交：保留真实进度与可执行邀请，不生成“大家的信”。
2. 只有祝福没有照片或故事：在最低成品规则允许时生成相应章节，不要求共创者补图才能收礼。
3. 所有日期未知：可播放照片且说明时间未补充，不生成虚假年代区间。
4. 没有单位、Logo 或简介：省略非必需模块，不留大片空白或强迫填占位字符。
5. 原声无法转写但技术可播：按原声允许范围展示，不猜字幕，也不把它用于未经确认的信件文字事实。
6. 候选缺少参与者可分享内容：通知承接展示真实准备状态，禁止回退到私人整包。
7. 拆封后无人继续投稿：历史礼物可重看，不制造空通知或要求签到。

### 13.5 延伸能力边界

礼后游戏化属于 P1 增强：共同补充一个年代／事件、老照片猜年份、同一事件多视角接龙。每次参与应形成可保存的照片、故事、关系或时间资料；没有可靠答案时只标待确认，不由 AI 生成标准答案。首版不以积分、排行榜、连续签到惩罚作为关系维系方式。

打印、公开传播、导出和数字形象需独立产品范围与授权。内部长期保存不自动授权上述用途，也不能因为采购方需要宣传就默认对外开放全部共创素材。

## 14. 质量、可访问性与指标

### 14.1 不可妥协的质量要求

1. 网络断开、返回前台、重新登录后不把未发送内容显示成已发送。
2. 每次写操作得到清晰的处理中、成功或失败；不弹成功提示但状态仍旧。
3. 本人账号切换不能遗留前一账号的内容、联系人、缓存和 AI 输入。
4. 相框离线可播放已校验包；包不完整不进入正式开场，失败不破坏旧可用包。
5. 长文、未知日期、0 项材料、超过目标人数、长单位名、照片横竖比例均有可用布局。
6. 操作支持明确焦点与大触达区域；故事／照片拖拽提供可访问的替代移动方式。
7. 相框大字号、高对比、字幕、手动控制和减少动态可用；动态不能影响阅读。
8. 用户个人资料、手机号和精确生日不进入普通日志、链接、公开分享图。

性能、设备存储、包大小、处理超时和运营响应的具体 SLA 见 D-09，需按实际设备与服务压测确定。

### 14.2 指标口径

| 指标 | 口径 |
| --- | --- |
| 邀请参与转化 | 符合权限并打开邀请的去重用户中，产生有效提交的比例 |
| 共创完成率 | 开始身份关系流程的参与中，有效提交的比例；跳过单步不算失败 |
| 可用素材率 | 技术、安全、来源与用途均通过的素材数／已提交素材数 |
| 成品形成率 | 达到最低交付条件并冻结的项目／开启收集项目 |
| 按期就绪率 | 在实际交付截止前内容包可用的项目比例；不把锁版当下载就绪 |
| 拆封率 | 已交付项目中产生真实 gift_opened 的比例 |
| 成品回访 | 获通知且有权查看的参与者中，打开成品的比例 |
| 礼后内容增长 | 新增有效送时光、回应及记忆数量，不以打开时长代替 |
| 提醒行动率 | 有有效提醒实例的人物事件中，产生对应成功提交的比例 |
| 多收件发送可靠性 | 每条收件投递成功率、部分失败率、重复投递数量 |

| 编号 | 输入／操作 | 必须结果 |
