# 拾光叙长者 App 完整产品 PRD V1.0

版本：2026-10-10。适用：产品、交互、视觉、客户端、服务端、AI、测试。产品范围为长者使用的 App，不是展示网站，不是共创者小程序，也不是相框播放器。

本文是正式产品的实现规格；文末单独列当前网页原型差距。页面不得出现固定案例介绍、实现原理、演示操作或虚构成功状态。新增工程参数为本版建议基线，开发前由负责人确认；不改变跨端 PRD 中的内容权限、礼物锁版和账号规则。

## 1. 产品目标与边界

让长者自己留下生活和回忆，方便地给亲友发送近况，并在不会操作时得到小叙帮助。以少步骤、看得懂、能说话、不会误发为基本原则。

三个核心能力：

1. 拾光碎片：上传照片，说话记录人物、时间、地点和标签，保存属于自己的记忆。
2. 发日常：选照片或拍照，说一句话，明确选择亲友并发送。
3. AI 小叙：文字／按住说话的对话式使用帮助；轻提醒有新来信；通过对话协助添加家谱成员。

“我的”为支撑区域：个人资料、我的拾光、发过的日常、我的亲友、设置。不是第四类内容业务。无朋友圈、排行榜、互动积分、群聊、共创者评论流、数据驾驶舱。荣休仪式和日常相框仍由相框端承担，不在 App 首页重做仪式入口。

## 2. 跨端分工与身份

| 系统 | 职责 | 与本 App 的关系 |
| --- | --- | --- |
| 长者 App | 长者自己的碎片、日常、亲友、操作帮助 | 本文范围 |
| 小程序 | 共创者／统筹者共创、赠礼、持续联系 | 同一个人的账号身份跨端一致，角色按上下文判定 |
| 相框 | 仪式播放、日常收礼、记忆浏览、长者回应 | 获授权同步内容；共用家谱和人物标识 |
| 展示网站 | 场景演示和工程沟通 | 不承担正式身份、送达或云端存储承诺 |

- 同一自然人以稳定 userId 表示；小程序授权身份与 App 登录方式映射同一账号，不按昵称自动合并。
- 家谱中的 personId 表示被记载的人，可没有账号；accountId 是可选关联。亲属关系不等于账号绑定、通讯录授权或消息接收许可。
- 联系人姓名取账号资料；长者设置的备注只对本人展示，不能改对方账号姓名。
- 当前演示以陈明远为长者。正式产品从登录资料读取，不预置陈老师、学校、亲属姓名或演示家谱。

## 4. 视觉与长者交互规范

继承小程序当前暖白和棕色视觉：底色 #FBF3EB、纸面 #FFFAF4、主动作 #72543D、正文 #2F2A24、辅助色 #786C60、分隔线 #E8D9C8。使用同一中文无衬线字体栈，避免以装饰衬线表达大量正文。

- 正文建议20–22逻辑像素，主标题26–30；辅助信息不小于16；系统字号放大到200%时可换行，不裁掉操作。
- 主按钮至少64高，图标与文字并列；次级触控区至少48×48。不得用小图标代替“保存”“发送”“返回”等关键动作。
- 每页只突出一个主操作。选照片与拍照可以并列，互不替代。
- 暖白分区、大间距、轻分隔线。避免多层边框、说明卡套卡、连续长段文案、操作前案例介绍。
- “我的”使用居中头像姓名、简短编辑入口、大行菜单，齿轮独立放右上角。无人物小传、统计卡和宣传入口。
- 小叙在底栏、页头、气泡统一使用既有小男孩形象。不得替换为通用机器人／聊天图标，不在非小叙页面持续悬浮遮挡内容。
- 页面随真实设备安全区适配，不画假的时间、电量、Wi-Fi；输入键盘弹出时输入栏保持可见，主内容可滚动。
- 颜色不是唯一状态依据，选中项配勾选和文字；录音同时显示文字状态。支持屏幕阅读器、键盘导航、减少动态效果。

## 5. 首次使用与登录 E00

1. 展示产品名称与“登录”，不先要求完整个人档案。
2. 支持与既有账号体系一致的手机号验证／微信身份绑定方式；具体SDK由客户端方案确定。
3. 同一手机号遇到已有小程序账号，验证后进入同一 userId；不能仅根据同名联系人合并。
4. 首次进入只请求登录所需授权。照片、相机、麦克风、通知权限均在使用对应功能时请求。
5. 登录失效时保留加密草稿，重新登录后仅恢复相同账号的数据；退出登录清除可读会话与当前账号缓存索引。
6. 登录取消可返回登录页；不会静默切换到另一个人的陈老师案例或显示其他人的家谱。

## 6. 拾光碎片 E01–E02

### 6.1 默认页

标题“留下这段回忆”；大“选照片”区域；一条“没有照片，也可以直接说”；大“点这里说话”按钮；“也可以打字”次入口；底部“保存”。默认不放标签列表、自定义表单或二次确认页。

内容合法条件：照片、有效录音、非空白文字三者至少一项。只选标签不构成碎片。没有内容时保存不可用，并保留正常颜色对比和无障碍提示。

### 6.2 照片

本版建议一次最多3张，每张原始文件不超过20MB。客户端支持常见相册格式，HEIC由系统或服务端转兼容预览；不支持的类型明确告知，不能生成坏缩略图。超限选择保留先前照片，不静默丢失。

逐张展示缩略图、删除按钮；点图放大返回原编辑页。裁剪和美化非首发必选。保留原始资产及方向信息，上传预览压缩不覆盖原图。默认不公开精确定位等EXIF信息。

### 6.3 说话与文字

碎片与日常采用“点一次开始、点一次结束”，便于长者长时间讲述；小叙聊天另用按住说话。录音建议最长60秒，到时停止并保留。用户可回听、删除、重新录；重录成功后才替代上一次录音，失败不得丢原录音。

语音转文字必须异步，不阻塞原始录音保存。识别失败显示“录音已留下”，可重试识别或直接保存，不把网络失败解释为没有说话。文字最多500字；空白裁剪，不能静默截掉较长识别结果，应保留原录音并提示精简文字。

打字入口按需展开。语音原文与编辑后文字分别保留；用户的编辑不被迟到的识别结果覆盖。识别中继续打字时，将新结果作为可接受的候选。

### 6.4 语音标签与照片时间

说“这是和女儿去杭州旅行时拍的”可生成“女儿／杭州／旅行”候选。人物、地点、话题分别存储，家人同名时不自动绑定 personId。标签可删除或修改；首次提取后显示简短确认，不在空白页要求填一堆标签。

日期使用 takenAt、precision（day/month/year/unknown）、source（EXIF/user/speech）、confidence。用户确认优先；识别出的含糊日期不补成确定年月日。“那年夏天”不能编造年份；“大概2010年”记录年份及不确定性。

单条多照片分别存拍摄时间。保存列表默认按创建时间倒序以便找回；“按回忆时间”浏览按拍摄时间升序，不确定日期置后、同时间稳定排序。不得把上传日期冒充拍摄日期。

同步到相框后使用相框既有排序／拼图规则；图中出现4个人不是合并4张照片的条件。App自身上传碎片不改写已经锁定的荣休仪式版本。

### 6.5 保存与结果

保存直接执行，不再出现“下一步看看内容”的强制页面。按钮锁定并生成幂等键，防重复点击创建多条。

- 云端确认成功：显示“已保存”，可以完成或查看。
- 离线仅保存本地：显示“已保存在本机，联网后继续上传”，不声称云端或相框已收到。
- 上传失败：内容保留，可重试；退出不丢草稿。
- 保存后编辑属于新revision，旧版可恢复；删除需要确认，先软删除进入恢复期（建议30天）。

保存默认仅自己可见。相框同步必须具备本人绑定和明确的同步授权；不能因为加入家谱就对全家公开。

## 7. 发日常 E03–E06

### 7.1 内容编辑

选照片与拍一张并列；拍照取消回编辑页，原内容不变。照片／语音／文字均可独立发送，限制复用碎片规则。草稿与碎片草稿独立，不互相带入内容。

### 7.2 选择收件人

显示已确认可联系的账号：头像、本人备注或账号姓名、关系、多选勾选。姓名缺失使用可辨识的账号资料，不展示生硬数据库ID。家谱未关联账号人物不能成为收件人。

建议单次最多20人；达到上限解释原因，不清空选择。选中项置顶或提供“已选N人”，返回编辑仍保留选择。对方已删除、停用、屏蔽或撤回联系许可时，发送前重新校验，并指出不可发送的人。

### 7.3 确认发送

列明全部收件人和本次照片、文字、声音；最后按钮“发送”。多选发送是分别私信，不建群、不公开其他收件人。小叙不得替用户确认发送。

### 7.4 状态与回执

每位收件人独立拥有：排队中→发送中→服务端已接收→已送达；读取／回应另存，可未知。HTTP请求成功仅代表服务端接收，不意味着对方已看。App被杀进程后任务由可恢复队列继续，使用同一幂等键。

全部成功、部分成功、全部失败使用不同文案。部分失败只重试失败对象，成功对象不能重复收到。离线显示“等待联网”，用户可以取消尚未发送的任务。已送达的撤回能力若后端不支持，不提供虚假撤回按钮。

消息默认发送到对方账号；是否展示在其相框由对方的接收范围控制，不自动向其所有设备或家人广播。

## 8. AI 小叙 E07

### 8.1 对话界面

小男孩头像配简短问候；会话气泡、两个常用问题“怎么存照片／怎么发给亲友”；底部固定输入条，默认“按住说话”，左侧键盘切换打字。不要多个AI入口叠加、整屏模板教学或主动弹出长篇欢迎。

### 8.2 按住语音

- 按下开始请求麦克风；权限弹窗结束时若已松手，不启动录音。
- 有录音指示才表示正在录制；松开结束并发送到小叙会话；上滑超过约65逻辑像素转为取消，移回可恢复，松手时决定是否发送。
- 少于0.6秒不发送，提示重试；60秒自动结束。中断、来电、锁屏、切页、pointercancel均停止并清理音轨；未完成录音不静默发送。
- 回听音频与识别文字可并存。识别失败保留原音频，可重试或改打字；未接入语音模型时不能假装已听懂。
- 发送给小叙的录音不会自动发送给亲友，也不会自动变成拾光碎片。

### 8.3 使用帮助

短句说明下一步，最多一个主行动按钮，例如“去选照片”。可理解“我想给女儿发照片”，打开日常编辑并在关系唯一且已绑定账号时预选女儿；仍由用户确认。无法确定对象时先问是哪一位。

复杂问答和主动聊天可延后，操作帮助、失败解释与用户确认不能省略。不得编造上传成功、对方已读、家庭关系或系统权限状态。

### 8.4 来信提醒

小叙只提醒“您有一封新来信，要看看吗”，不在首页自动展示正文、照片或朗读内容。点击查看才进入E17。通知锁屏默认仅显示通用提示，敏感内容不外露；关闭提醒后仍能主动查看未读。

提醒按账号消息去重，同封信不反复打招呼。免打扰时段建议21:00–08:00，可设置；勿用强弹窗打断录音或确认发送。系统通知权限与App内提醒偏好分开。

## 9. 小叙对话添加家谱 E15

### 9.1 两个入口

家谱页增加“跟小叙说，添一位家人”，或直接对小叙说“把我女儿加进家谱”。进入同一对话流程，继承当前选中的参照人物和家谱ID。

### 9.2 逐步确认

例：“这是我儿子陈知远，他和沈宁有个孩子叫陈星禾。”

1. 保留原语音及转写；提取候选人物与关系，不立即写入正式家谱。
2. 显示一句理解：“陈知远是您的儿子，沈宁是他的配偶，陈星禾是他们的孩子，对吗？”
3. 信息缺失时一次只问一个问题。“沈宁和陈知远是什么关系？”不能因为两人有孩子就擅自认定婚姻。
4. 性别、出生日期、是否在世、婚姻状态不是创建人物必填，不从姓名推断。“孩子”不强迫自动变成儿子／女儿。
5. 用户修改候选后展示简明卡片：姓名、相对谁、什么关系、是否关联账号。按钮“确认加入家谱／再改一下”。
6. 确认后以事务写入人物与关系，返回原家谱并定位新增成员，提供“撤销本次添加”。

### 9.3 同名与去重

同一 accountId 已在该家谱时提示定位原人物；同名但没有账号时列出候选和关系让用户选择“就是这位／另一个人”。模糊识别“晓荷／晓禾”不自动合并。未说姓名可建立“姓名待补充”的草稿，必须明确它不是已识别账号。

### 9.4 账号关联是独立动作

新增人物可以没有账号。不得把小叙识别的名字绑定到同名小程序用户。通过邀请或账号确认建立关联，接受前为待关联；对方拒绝不删除家谱历史人物。家谱照片识别也只能建议候选，不直接认人。

### 9.5 关系一致性与危险操作

禁止自己成为自己的父母、亲子有向环、重复同一关系边。对冲突关系先提示，不能自动覆盖旧事实。离异、再婚、收养、继亲、非二元性别等关系通过明确关系类型表达，不强制二选一父母或只有一对配偶。现任／历史配偶需有效期或状态，不能用新配偶覆盖旧家庭。

“删掉某某”不直接执行：展示影响范围，要求确认；有关联账号、共同维护或后代时不能级联删除全部后代。撤销新增仅撤销本次变更集；之后有其他人编辑的节点转为冲突确认。

### 9.6 失败与离线

语音识别失败保留录音并允许手动改姓名／关系；模型超时保留草稿；用户中断回来恢复未确认候选。离线可保存家谱草稿但不宣称已同步。部分关系写入失败整体回滚，避免出现只有孩子没有来源关系的半成品。并发提交使用版本号校验。

## 10. 我的 E08–E09

头像、姓名居中，编辑入口明确；右上角齿轮进入设置。仅列“我的拾光／发过的日常／我的亲友”。不放“学生们熟悉的陈老师”等人物介绍，不放统计和赠礼宣传。

个人资料修改姓名与头像；头像校验、上传失败保留旧头像。建议姓名1–24字，前后空白去除。修改需服务端确认后传播到本人其他端；亲友的私人备注不会被覆盖。不可通过改姓名修改账号归属。

## 11. 我的拾光 E10

默认最近保存优先，卡片展示缩略图／语音标识、简短文字、保存时间和同步状态。空态“还没有留下内容”配“去留一段时光”；不放示例内容伪装用户历史。

详情可回听、看图、修改文字与标签、调整已确认拍摄日期。长者原始录音保留，修改不强迫重新录。删除二次确认并说明已同步到相框的影响；删除个人记忆与撤回已发出的日常是两件事。

下载和清缓存不得误删云端原件。分页加载、加载失败重试、离线已缓存查看均需支持。

## 12. 发过的日常 E11

按发送时间倒序；展示内容摘要、收件人、每人状态。多人发送汇总为一次日常，点开才看各收件人状态，避免刷出重复内容卡。

失败可修改后作为新版本发送，或使用原幂等任务重试；必须明确是哪一种。读取状态未知就显示已送达／状态未知，不用“已读”代替。清除本地记录不代表对方收件箱被删除。

## 13. 我的亲友与家谱 E12–E14

### 13.1 亲友账号卡片

“家人／亲友”分段切换。亲友卡片显示头像或姓名占位、昵称／备注、关系；点击详情可发日常、修改本人备注。关系标签来自双方已确认的联系语境，不自动授予家谱编辑权。

首版有姓名搜索、关系筛选和空态；小名单不强制显示复杂筛选器。用户停用账号后保留必要的历史显示快照，但不允许继续发送。

### 13.2 家谱布局

以当前长者personId为参照，纵向按代际，横向夫妻或同辈；夫妻横向连线，父母子女由明确节点或组合连线向下。线不穿过人物卡片，交叉不可避免时高亮选中人物的相关边。

默认大字局部视图定位到“我”，支持上下左右滑动；“看全家”适配整体，“回到我”恢复可读尺度。全图缩略不作为唯一阅读方式，提供大字名单视图。家庭人数增加时不无限缩小默认文字。

图中展示头像、姓名、相对当前长者的关系；详情补充准确关系、账号关联状态。亲友非家人不强行放进家谱。未知人物用占位，不凭空补齐四代。真实空家谱只有本人，加人入口可见。

全屏可作为增强，但退出保持视角；触控拖动不能误触人物。节点与名单均支持屏幕阅读器，读出姓名和关系。

### 13.3 维护与共享

本人管理自己的家谱；家庭共享树需要familyId、成员角色和明确授权。亲属不是天然管理员。看家谱权限、看人物资料权限、看碎片权限、发日常权限分别判定。

允许未关联账号、已故人物和未知生卒年月。已故不自动触发账号注销；禁止自动弹出生日营销提醒。家庭关系信息只向被授权家谱成员可见，不暴露给所有学生、同事或普通联系人。

## 14. 设置 E16 与来信 E17

设置：个人资料、更大字号、提醒、账号与隐私。更大字号立即生效、持久保存，返回不丢位置。提醒包含系统权限状态、App内开关、免打扰；未接入实际通知时原型不显示假开关。

隐私说明必须与真实采集和SDK一致；提供退出登录、账号删除申请和数据导出入口的服务端流程。删除账号需要再次身份验证与影响确认，不用前端清缓存冒充注销。

来信点击后主动展开，显示发送人、时间、内容；语音不自动播放。若支持回应，必须用户主动点击或录音确认，AI不能自动回信。原消息撤回或资产失效显示可理解状态，不报数据库错误。

## 15. 数据模型与跨端契约

| 实体 | 必要字段／规则 |
| --- | --- |
| User | userId、显示姓名、头像资产、绑定身份、状态、版本 |
| Contact | ownerUserId、targetUserId、remark、关系标签、联系许可、版本；身份不以姓名作为键 |
| Person | personId、familyId、name、可选accountId、可选日期精度、隐私范围、来源、版本 |
| Kinship | edgeId、familyId、fromPersonId、toPersonId、type、有效期、确认者、版本 |
| Fragment | id、ownerUserId、assetIds、原始录音、转写、编辑文字、标签、创建时间、拍摄时间及精度、可见性、同步状态、revision |
| Daily | id、senderUserId、assetIds、文字／录音、clientRequestId、收件人ID列表、创建时间 |
| Delivery | dailyId、recipientUserId、status、失败码、serverAcceptedAt、deliveredAt、readAt可空、重试次数 |
| AI session | sessionId、ownerUserId、消息、语音资产、意图、工具候选与执行结果，不把候选当已写入结果 |
| Family proposal | proposalId、sessionId、人物／关系候选、冲突、baseRevision、确认者、状态、changeSetId |
| Asset | assetId、类型、大小、hash、上传状态、原件与预览地址、访问授权；私密资产不能永久公开URL |
| Notification | messageId、recipientId、类型、未读状态、提醒去重键、隐私级别 |

照片同文件hash可复用资产，但不能因此把两条不同回忆自动合并。客户端时间不可信，存服务端创建时间；拍摄时间不得被覆盖。

## 16. 服务与实现接口建议

接口名称供实现协调，可调整路径但必须保留语义：

- 身份／资料：获取当前账号、更新资料、关联小程序身份、退出／注销任务。
- 资产：申请上传、分片／断点续传、提交校验、短时访问凭证。
- 碎片：创建幂等、分页查询、带revision更新、软删除、恢复、设备同步回执。
- 日常：提交收件人列表、查各人送达状态、取消未发送、重试失败收件人。
- 亲友：已授权联系人查询、修改私人备注、邀请与接受。
- 家谱：读取树及revision、生成候选、校验关系、用户确认后提交changeSet、撤销、邀请关联账号。
- 小叙：语音识别、对话、受权限约束的工具建议；写操作必须携带用户确认令牌与幂等键。
- 提醒：未读索引、通知偏好、读取内容、提交回应。

客户端不能靠隐藏按钮实现权限；服务端每次按当前用户验证familyId、personId、assetId、recipientId访问。跨端变更通过增量版本同步，离线冲突不使用无条件最后写入覆盖。

## 17. 异常与边缘验收

| 场景 | 必须行为 |
| --- | --- |
| 相册／相机取消或拒绝 | 原内容保留，仍可只说话／打字 |
| 麦克风拒绝、忙碌、设备缺失 | 明确提示，允许改打字，不显示假录音状态 |
| 按住时权限返回前已松手 | 不录制、不发送 |
| 上滑取消、页面隐藏、触摸中断 | 停止音轨，无新语音消息 |
| 录音太短／静音／编码失败 | 不伪造转写，原稿保留，可重试 |
| 长录音自动截止 | 明确结束并可回听，不持续后台采集 |
| 识别结果迟到 | 不覆盖用户已编辑内容 |
| 同名人物、关系不确定 | 询问确认，不自动绑定账号 |
| 语音识别错姓名 | 确认卡可改，未确认不入树 |
| 重复添加／关系成环 | 阻止并定位问题，不破坏原家谱 |
| 修改家谱时另一端已更新 | 提示冲突，重取版本，保留候选 |
| 断网创建家人 | 本地草稿，不显示云端成功 |
| 账号邀请被拒绝 | 保留未关联人物，不允许发送 |
| 发送对象失效 | 标出失效人，其他对象经确认可继续 |
| 多人部分失败 | 单人状态清晰，仅重试失败对象 |
| 连点保存／发送 | 同幂等键单条结果 |
| 上传中杀进程 | 可恢复任务，不能产生不可追踪半条记录 |
| 空间不足 | 停止新增录制／缓存，保留已有内容，不清除用户资料腾空间 |
| 登录切换用户 | 本地私密数据隔离，不展示前一位长者资料 |
| 超大字号／小屏／横屏 | 主按钮可达，标签栏不盖内容，家谱可用名单阅读 |
| 家谱超过100人 | 按分支加载，定位本人，不能强行压成不可读微缩图 |
| 新来信发生在录音中 | 等待合适时机提醒，不打断和自动朗读 |
| 提醒关闭／免打扰 | 不主动打扰，主动访问仍可看未读 |
| 相框未联网 | App显示待同步，不声称相框收到 |
| 删除后另一端打开旧内容 | 遵守版本与权限，显示已删除状态 |
| AI不可用 | 保留录音、提供手动姓名／关系填写与确定性操作帮助 |

## 18. 性能与可测试指标

本版建议目标：主页面缓存后可操作时间≤2秒；本地点击反馈≤100毫秒；照片预览≤1秒（不含系统相册）；列表分页建议20条。上传和识别显示真实进度或状态，不用固定定时器伪造完成。指标需标明设备、网络和样本量。

首发至少覆盖主流iOS／Android手机，系统字号200%、屏幕阅读器、弱网断网、锁屏录音中断、权限拒绝、微信账号跨端绑定。浏览器模拟音源测试不能代替真机麦克风／相机验收。

只采集完成率、失败类别、耗时等必要事件；默认不把语音正文、家谱姓名、私信内容写入分析日志。核心指标：首次保存完成率、发日常完成率、误发取消／重复发送率、家谱候选修正率、长者独立完成任务率。不得用日活或消息量驱动社交噪音。

## 19. 开发阶段与发布门槛

P0：账号隔离、三个核心流程、资料与记录、家谱／亲友读取、发送许可、基础设置、语音帮助与转写、确认式家谱添加、离线草稿及失败恢复。对话添加依赖AI服务，但必须有手动兜底。

P1：复杂自由聊天、扩展自动整理、丰富家谱照片关联、更多跨端推荐。不得以延期AI聊天为由取消基本语音录入和确定性帮助。

可发布的正式App必须通过真实账号、云存储、收件人送达、权限、真机、家谱写入冲突和数据隔离验收。网页原型上线不等于正式App发布。
