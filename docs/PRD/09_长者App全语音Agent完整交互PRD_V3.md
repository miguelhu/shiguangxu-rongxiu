# 拾光叙长者 App · 全语音 Agent 交互 PRD V3

> 历史规格：当前完整App需求以 [11_App完整PRD_V4](11_长者App完整产品PRD_V4.md) 为准，账号与跨端同步以 [12_公共PRD](12_账号内容与相框同步公共PRD_V1.md) 为准。本文不再作为当前导航、页面与功能范围的开发依据。

版本：2026-10-13。状态：产品开发规格，非全部能力已上线声明。

本文为长者 App 当前交互主规格，覆盖07和08中的首页、导航、输入、拍照、选项与连续会话规则。07中的账号、跨端权限、家谱身份、内容归属及消息回执规则继续适用。展示网站的手机框、案例选择器、步骤编号和“演示”提示不属于正式 App。

## 1. 产品目标

长者通过说话、拍照或选照片，记录自己的拾光碎片、给亲友发送日常，并在需要时得到小叙帮助。小叙是持续理解上下文的助手，不是每完成一项任务就重新开始的问卷。

**所有 App 自有页面的可执行操作必须同时提供语音路径与可点击路径。** 包括导航、打开相机、切换镜头、拍照、重拍、选照片、勾选／取消选项、修改文字、挑选亲友、保存、确认发送、取消、返回、查看记录、调整设置和维护家谱。不得把“能语音输入正文”当成全语音操作完成。

语音不绕过系统相机／麦克风／相册授权、系统登录验证、设备解锁或付款等系统安全界面。首次授权仍由系统要求用户确认；授权完成后回到原任务继续。对此应明确提示一次，不承诺零触屏首次使用。

## 2. 导航与双入口

顶部稳定保留“拾光”“我的”及圆形相机按钮，分别提供文字可读标签或无障碍名称。相机不是新的聊天助手，也不重复增加底栏。

- 拾光：欢迎语、连续聊天、按住说话、文字输入和媒体入口。
- 圆形相机：直接取景→拍摄／选图→补充一句话或声音→选亲友→确认发送。不必先与小叙聊天；但每个步骤都能用语音执行。
- 我的：个人资料、我的拾光、发过的日常、我的亲友（家谱／亲友）、设置。

“打开相机”“给女儿拍张照”与点击相机进入同一相机状态。“回到聊天”恢复原对话及未完成草稿，不清空。不同草稿通过 taskId 分开，不能把新拍的日常自动混进之前的回忆。用户明确说“把这张也添进去”时才关联指定回忆。

## 3. 页面级语音契约

| 页面／状态 | 语音示例 | 结果与确认 |
| --- | --- | --- |
| 所有自有页面 | 回去／取消／打开我的／回到拾光／你能帮我做什么 | 执行当前可用动作；有未保存修改时先询问保留还是舍弃 |
| 欢迎／聊天 | 记个回忆／给晓禾发日常／打开相机 | 切换任务意图，保留前序聊天 |
| 回复后的选项 | 第一个／选存起来／不是这个／换一种说法 | 按当前可见选项的稳定ID执行，与点击同一路径 |
| 相机 | 拍一张／三秒后拍／换前置／换后置／重拍／用这张 | 取景、可取消倒计时、拍照或确认使用；打开相机不等于拍照 |
| 相册 | 看下一页／选第二张和第四张／取消第二张／选好了 | 对 App 内可访问缩略图执行选择，显示勾选和总数 |
| 日常编辑 | 加一句“今天很开心”／删掉最后一句／听一下录音 | 定位对应内容并预览修改；指代不明先问 |
| 亲友选择 | 发给女儿／再加上周宁／不要周宁／选好了 | 匹配稳定accountId；重名给候选，不按猜测发送 |
| 发送确认 | 读给我听／确认发送／改一下／先不发 | 朗读、提交或返回；明确确认才执行发送 |
| 保存回忆 | 先存下／把刚才那句也补进去／换个话题 | 保存事务成功后反馈；同记录追加或新建任务 |
| 我的拾光 | 找和学生的合影／打开第二条／读这段／改标题 | 仅搜索有权访问内容；结果必须可追溯到实际记录 |
| 发过的日常 | 看发给晓禾的／重试刚才失败的 | 显示真实状态；只重试失败对象，不向已成功对象重发 |
| 亲友／家谱 | 打开家谱／这是我女儿／加一位家人 | 收集关系、身份后显示确认卡；不自动绑定账号 |
| 个人资料／设置 | 把字号调大／关闭自动朗读／改我的称呼 | 可逆设置立即反馈；账号删除等敏感操作单独核验 |

系统相册选择器不能被 App 的 Agent 控制。要满足“选第二张”的语音体验，正式客户端需在获得系统许可后使用 App 自有相册选择页，或将系统选择结果返回 App 后再语音调整。有限相册授权只展示获准素材，扩大范围要再次走系统授权。

## 4. 语音入口与收听状态

各页面保留可触达的语音控制。默认支持按住说话；另提供“一次点击开始，再点结束”的免长按模式。相机取景中以小型麦克风状态条显示，不遮挡被拍人物和快门。

状态：未收听→请求权限→正在听→正在识别→理解／执行→回复。拒绝、超时、不可用分别呈现真实状态，保留文字和按钮替代。不能未获授权就持续录音。

用户主动开启“连续语音”后，可以在前台当前任务中连续发指令；清楚显示正在收听和停止入口。进入后台、锁屏、退出账号、切到系统权限界面时停止收听；回来不偷偷恢复。静默时限由配置确定并真机验证，超时提示后暂停，不丢任务。

用户说话时停止小叙朗读，避免回声被当作指令。TTS文字、播放状态和音量可控；不自动朗读别人来信正文。录音权限与相机权限独立，拒绝其中一个不阻止另一个。

## 5. AI 回复与快捷选项

回复先回应用户刚说的具体内容，再在必要时问一个问题。语气亲切、平等，不哄小孩，不无根据推断开心、孤独或家人意图。不因信息缺项反复追问。

只在有决策需要时提供选项，通常2—3个；没有选项时也能继续自由说话。选项是建议，不是强制问答。

| 场景 | 回复示例 | 可点击／可说出的选项 |
| --- | --- | --- |
| 收到照片 | 照片放好了，想聊聊它，还是发给亲友看看？ | 存起来／发给亲友 |
| 一段讲述 | 想接着说，还是先看看我帮您整理的一小段？ | 继续讲／帮我整理／保留原话 |
| 改写预览 | 这样写像您想说的吗？ | 就用这段／再口语一点／用原话 |
| 找照片 | 是这张吗？ | 就是这张／不是这张 |
| 姓名不确定 | 您说的是女儿陈晓禾吗？ | 是她／换一位 |
| 发送前 | 这张照片和这句话，发给陈晓禾，对吗？ | 确认发送／改一下／先不发 |

每组选项携带 suggestionSetId、optionId、label、actionType、targetId、有效taskId和stateVersion。“第一个”只对应当前有效的一组选项；多组选项同时可见或刚切页时必须澄清。“好的”仅在唯一、无风险的明确提问中可作为选择；不能把模糊应答视为发送／删除授权。

用户说同义表达走同一动作，如“给她看看”映射分享意图，但对象未定时不能执行。旧选项失效后不执行过时动作，应解释并展示当前选项。点击和语音竞态使用同一幂等键，不能重复保存或发送。

## 6. 相机全语音流程

1. “打开相机”→展示取景；无权限请求系统授权，授权后继续。
2. “换前置”→切镜头成功反馈。设备无该镜头时说明，保留现有取景。
3. “拍一张”→拍照；“三秒后拍”→可见且可听的倒计时，任何时刻“取消”终止。
4. 拍摄成功→展示照片和“用这张／重拍／取消”。拍摄失败不跳转，也不生成空图。
5. “用这张，发给女儿”→照片加入日常草稿，解析对象，显示编辑／确认状态。
6. “加一句今天出去走了走”→文字可见；“读一遍”只朗读即将发送内容。
7. “确认发送”→服务端接受后显示发送中，按真实回执更新。

相机开启时语音监听不能要求退出取景；客户端需验证摄像头与麦克风并行占用。调用系统相机时若无法并行监听，返回 App 后恢复确认；正式版本必须提供 App 内拍摄以满足完整语音路径。退出取景立即释放摄像头。不得在后台拍摄。

## 7. 持续会话、任务与保存

一段会话可以有多项任务，但当前只设一个明确的执行焦点。保存结束的是当前写入操作，不是聊天。没有“再记一段才能继续”的页面。

用户补充原故事→更新原memoryId；明确换话题→新taskId与memoryId。无法判断“那次”“这个”指向时给候选，不擅自合并。分享记录使用独立ID，不能覆盖回忆。离开页面保留草稿，重新进入可恢复；正式产品本地加密草稿与云端同步策略需配合账号权限。

保存前无最低字数、必填年份或完成度门槛。有实际照片、录音或叙述之一即可保存；仅说“帮我保存”不构成回忆正文。保存失败保留原稿，不报告成功。用户舍弃只清除本次未保存修改，已保存记录保留；舍弃也可语音确认。

## 8. AI 整理、检索与丰富度

整理保留原始语音、转写和整理稿的关联，不改人名、年份、关系或关键事实。用户可语音逐句纠正，“不是老张，是老周”修改明确对象并展示结果。不得将操作指令混入故事。

段落→章节→小文表示内容逐渐丰富，不是进度任务，不是固定字数／百分比。时间不确定保留原话或未知，不推算为确定年份。

搜索仅在当前账号可访问的记忆范围执行，可结合人物、时间、地点、主题。没有结果就说明并给调整条件；候选不足时不拿固定图片假充命中。找到照片后可查看、讲故事、添加描述或分享，后续权限继续校验。

## 9. 收件人、发送与外部动作

亲属称呼与收件账号分开：personId不保证accountId存在。未绑定的家谱成员不能成为可达收件人；不把孙女误替换成女儿。重名显示关系、备注与可区分资料，支持“选第二位”。多人选择后必须读出／展示全部对象，允许语音逐一移除。

发送前展示当前内容版本和收件人集合；确认后如果任一项改变，旧确认失效，需重新确认。成功指服务端实际状态，不指点了按钮。排队、发送中、部分失败、全部失败、已送达分开；未读不能说已读。

删除记录、解绑亲友／相框、家谱关系变更等动作先明确对象、影响范围，再确认。用户话语中引用“删除”或回忆某人说“发出去”不应触发命令。登录验证码、系统权限不能由模型猜测或代填。

## 10. 视觉、声音与可用性

继承小程序和当前 App 的暖白纸面、克制绿灰主动作、大字与大按钮。正文建议21—24px，主要点击区域不小于48×48，系统大字模式不截断操作。字号、屏幕阅读器及横竖屏需真机验收。

小叙使用现有小男孩透明素材，在最新回复左侧探身出现，可短暂轻晃／问候，不带矩形底色、不挡文字、不持续跳动。减少动态效果设置下停止非必要动画。录音时不让角色动作掩盖监听状态。

回复选项靠近对应消息；新回复和选项进入视口，但用户主动翻看旧消息时不强制滚回底部。长回复优先分段，不能把所有动作堆成复杂表单。

## 11. 工程执行契约

客户端负责媒体、系统权限、语音输入、状态展示；Agent负责理解意图与提出结构化动作；业务服务负责权限、校验、幂等执行和真实结果。模型不得直接越过业务接口写数据。

建议动作信封：actionId、conversationId、taskId、stateVersion、source（voice／tap）、intent、entities、targetIds、confirmationToken、idempotencyKey。执行结果区分 succeeded／pending／needs_clarification／needs_confirmation／failed／cancelled。

流程：转写→区分命令与内容→解析指代／选项→权限及前置条件校验→必要确认→执行→根据真实结果回复。长耗时动作显示处理中，允许取消可取消部分；取消后迟到结果不得重新提交。重试时沿用同一幂等键。

媒体不上传到未获授权的服务；日志尽量记录意图与错误码，语音和图片不进入普通诊断日志。云端识别需明确授权与留存策略；离线仍可拍照和存本地草稿，不能假装完成云端发送／搜索。

## 12. 边缘情况验收

| 条件 | 必须行为 |
| --- | --- |
| 方言／低音量／识别失败 | 显示可修改转写，重说或打字，不猜命令 |
| 多次重复“拍照” | 单次曝光锁，拍后确认，不产生连拍误操作 |
| 倒计时中说取消 | 立即终止，保留取景 |
| 录音期间切页／来电 | 停止资源占用，保留已采集内容和任务 |
| 相册有限授权 | 只列获准图片，给扩展授权入口 |
| 同时说“第二个”和点击第三个 | 原子校验当前状态，只执行一次并反馈实际结果 |
| AI朗读“确认发送” | 不被ASR当成用户确认 |
| 修改收件人后迟到的确认 | 旧版本确认拒绝，重新读出对象 |
| 网络断开／恢复 | 草稿保留；外发需可见状态，不重复提交 |
| 保存后又补一句 | 同一回忆追加更新，旧内容不丢 |
| 退出再登录另一账号 | 不泄露前账号草稿、照片、搜索与亲友 |
| 拍照成功但保存失败 | 保留内存／本地临时照片，提供重试 |
| 设备不支持语音或相机 | 明确说明，保留选图、文字与触摸路径 |
| 亲友未绑定／取消接收权限 | 禁止发送，允许换人或存为本人回忆 |
| “他说删掉这张照片” | 识别为叙述或澄清，不直接删除 |

## 13. 端到端验收清单

以下为正式上线要求，不是当前原型通过声明。每项均需触摸路径和语音路径分别验证，并覆盖真实设备、授权拒绝和中断恢复。

1. 首页说“记个回忆”→讲述→“帮我整理”→“保留原话”→“存下”→继续补充同记录。
2. 收到AI选项后说“第二个”执行对应动作，过期选项与歧义数字不误执行。
3. “打开相机”→授权→“换前置”→“三秒后拍”→“取消”后不拍。
4. 打开相机→“拍一张”→“重拍”→“用这张”→给指定亲友→确认发送。
5. 相册“第二张和第四张”→取消第二张→继续，预览与选择一致。
6. 亲友重名澄清→多选→移除一位→朗读全部对象→确认发送。
7. 发送前“先不发”不产生发送请求；修改内容后必须重新确认。
8. “找和学生的合影”→真实检索候选→“不是这张”→调整条件→打开正确记录。
9. 我的→语音打开已保存内容→改标题→确认→返回位置保留。
10. 家谱语音添加→确认关系→保存personId；不自动建立accountId。
11. 关闭朗读／放大字号／返回均可语音操作，不影响会话。
12. 无网、失败重试、重复确认、后台切换与账号切换满足第12节。
