## 规则只在一处维护

| 问题 | 唯一维护位置 |
| --- | --- |
| 项目是否收集完成、能否锁版或移交 | 总览＋统筹工作台 |
| 页面入口、字段、用户操作和本端异常 | 对应各端PRD；App按当前V4，不同时参考旧版导航 |
| 账号／人物／设备、个人库、同步、删除撤销 | 账号内容与同步；各端只描述页面呈现 |
| AI编号、事实忠实、文风、候选与通用质量 | AI能力；四端相同功能复用同一编号 |
| Agent具体分期、工具、确认等级、数据合同、六卡规则 | 小叙Agent；不重复定义文风和通用编号 |
| 行为能否验收 | 主规格中的通过条件＋验收案例；案例不能放宽权限或扩大批次 |
| 为什么这样决定、过去怎么实现 | 产品资料；问卷答案和建议不自动升级为已确认需求 |

AI通用规范与Agent执行规格分别维护，是因为表达能力和业务执行职责不同；原AI规范、页面映射和内容验收已经合成同一份AI能力文档，不再拆成四份平级PRD。

## 开发如何定位

- 各端页面键加前缀：MP／CO／FR／APP。App使用APP.A00—APP.A24；旧的中文逻辑页名不再作为新接口键。
- AI-01—AI-28是能力编号，跨端保持一致；例如MP.C13、FR.M09和APP.A13都使用AI-03整理故事。
- T01—T24是业务工具，RQ是Agent分期需求，C是输入输出合同，均不代替AI编号。单次任务可调用多项AI能力及多个业务工具。
- 测试记录必须写明文档和ID，例如“相框/AC01”“Agent/AC-01”“App/A-01”，避免同样数字误认为同一用例。
- Agent先读第1.3节分期、第4.5—4.7节边界、第12节合同和第14节验收。首发P0为待团队估算确认的建议；完整能力目录不等于全部首发或已经实现。荣休礼AI集体信仍保留。
