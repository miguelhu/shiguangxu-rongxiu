# 荣休礼产品 PRD 文档集

建议采用“一份总 PRD＋三份端与角色专项 PRD”。荣休礼是一件跨端完成的产品：小程序负责共创和持续连接，统筹工作台负责形成可交付成品，相框负责仪式与日常收礼。单独按界面拆文档容易遗漏权限、锁版、排序、提醒等跨端规则；全部挤在一份文档中又不便于研发分工。

本目录定义真实荣休礼产品。它不把展示网站的浏览结构当作产品结构，不包含固定案例、模拟操作或讲解界面。AI 祝福信仍是成品功能。

## 文档使用规则

1. 总 PRD 是公共状态、数据归属和权限的唯一口径；专项文档进一步定义页面、动作和验收。
2. 文中“已确认”指已经明确的产品要求；“本版补充方案”用于把没有充分展开的细节写成可实现规则，并不冒充已有决策。
3. 总 PRD 第 16 节统一列出需要定案的事项。标为待确认的参数不能被研发默认为已有商业承诺，开发可先采用配置和可替换策略。
4. P0 是本版首发范围；P1 是增强能力。优先级是本版建议，需要结合排期确定，不能据此删除已经确认的核心功能。
5. 各文档中的 A、B、日期和数量仅用于说明算法、边界和验收，不是产品内置人物资料。

## 三条容易误解的规则

- **照片拼图看投稿者，不看照片里的人数**：先排序，再检测连续的同一作者、相同或接近时间的照片，按 1／2／3／4 张布局。四位不同作者不是自动合并条件。
- **“未完成／已完成”属于我对一次共创的完成情况**；“统筹中／已完成”属于我负责的礼物。共创提交成功不等于整个礼物已经交付。
- **收集结束通知、正式拆封通知、重要日子提醒是三种事件**，各自有条件、权限、内容版本和投递记录，不能用一条固定消息替代。
