# 荣休礼三端代码拆分

本目录从当前荣休礼互动演示中拆出三个**可独立安装、构建、运行的前端工程**。原项目 `ai-frame/prototype/rongxiu-demo` 保留，没有被改动。真实产品需求以 [荣休礼 PRD](docs/PRD/README.md) 为准。

| 目录 | 职责 | 本地地址 | 入口 |
| --- | --- | --- | --- |
| [miniapp](miniapp/README.md) | 共创者＋统筹者的同一个小程序界面工程；含人物、消息、送时光、发起、内容整理与成品预览 | `http://localhost:5191/` | `src/App.tsx` |
| [web](web/README.md) | 展示网站；角色体验、生命周期、案例、并排对照与讲解 | `http://localhost:5188/` | `src/v6/App.tsx` |
| [frame](frame/README.md) | 相框端；绑定前品牌页、仪式播放、照片故事、祝福信、声音与新心意 | `http://localhost:5192/` | `src/App.tsx` |

三个工程各有 `package.json`、`package-lock.json`、`index.html`、`src/`、`public/`，不通过运行时相对路径读取兄弟目录。分别运行：

```bash
cd miniapp && npm ci && npm run dev
cd web && npm ci && npm run dev
cd frame && npm ci && npm run dev
```

也可以在各目录运行 `npm run build`。构建产物位于该目录的 `dist/`。

## 代码现状与生产接入边界

这次拆出的是**当前网页原型的前端代码**，不是已经完成微信原生编译的小程序，也不是可直接安装在相框硬件上的系统包。小程序目录目前用 React/Vite 在浏览器展示微信式界面；相框目录用浏览器模拟相框屏幕。所有案例人物、提交、角色、二维码、验证码、通知与 AI 行为仍是演示数据或本机状态。

工程师转正式产品时，应保持这三个界面／角色边界，并按 PRD 接入微信小程序原生运行时与登录、项目和人物服务、真实媒体上传与审核、账号／设备绑定、短信与微信消息、不可变仪式内容包、相框设备运行时和离线同步。不能把本机 `localStorage`、示例二维码或固定验证码当生产实现。

为防止三份独立原型互相误读浏览器数据，miniapp 和 frame 使用各自的本机存储键；它们**不会自动共享提交结果**。真实三端由服务端项目 ID、人物 ID 和成品版本连接。网站继续使用原演示状态。

`public/` 为各自运行所需媒体副本，体积较大；分目录交付是为了每端可独立运行。后续可在正式 monorepo 中提炼共享设计令牌、业务类型与媒体协议，但不应把相框播放逻辑放回展示网站入口。

## 源码边界

- `miniapp/src/App.tsx` 只装配共创、统筹及其在小程序内的成品预览。原网站的左侧生命周期、顶部三角色切换、并排比较已从小程序入口移除。小程序内保留 `Frame` 预览组件，是为了统筹者确认成品，不代表小程序承担真实相框运行时。
- `web/src/v6/App.tsx` 保留原展示网站的完整导演式演示、讲解和案例选择；它不作为正式产品前端的唯一代码源。
- `frame/src/App.tsx` 只装配绑定、仪式和新心意，不使用网站的角色切换。`frame/src/v6/BlockCard.tsx` 抽出相框需要的内容卡，避免相框播放器依赖整页共创表单。

这次没有改线上域名部署；目录供研发交接、独立审阅与后续移植使用。
